# v0.4 프로젝트 작업 공간

개발 중인 네이티브 실행 파일은 `cargo run --bin idk --` 또는 `dist/idk-linux-x86_64`다.
기존 Python 설정은 자동으로 가져오지 않는다. 다음 안내는 구현된 기능에 맞춰 갱신한다.

## 프로젝트 연결과 환경

인수 없이 실행하면 프로젝트 화면이 열린다. `n`으로 기존 폴더를 연결하고 이름, 실제 csh/tcsh,
초기화 폴더, source 목록을 입력한다. `Tab`으로 필드를 이동하고 `F2`로 검토한 뒤 저장한다.
`Esc`는 입력 초안을 보존하며 돌아간다. 전체 동작은 `F1` 도움말에서 확인한다.

연결은 `.csh`를 실행하거나 Git 저장소를 만들지 않는다. `t`로 초기화 검토를 열고 승인한 뒤
새 셸을 준비한다. 검토는 실제 셸 파일, 정적 startup 파일과 HOME, 등록한 source 내용·인수·순서,
초기화/시작 폴더의 정규 경로에 연결된다. 변경 후에는 해당 범위를 다시 승인한다.
동적·중첩 source의 모든 의존성을 추적하는 것은 아니다.

초기화 폴더는 공통 startup과 source를 수행하는 위치다. 터미널 시작 폴더는 그 뒤 이동할 위치이며
프로젝트 루트 밖 테스트 폴더도 사용할 수 있다. 현재 셸의 cwd와 프로젝트/Git 대상은 별개다.
프로젝트마다 필요한 접속 환경을 메모리에서 전달하며 환경 값은 설정·일반 로그에 저장하지 않는다.
셸 안에서 바꾼 임시 변수와 alias를 다른 셸에 자동 복제하지 않는다.

source 편집은 경로와 각 인수를 별도 필드로 받는다. tcsh는 입력한 인수를 그대로 전달한다.
전통 BSD csh는 source 인수를 지원하지 않아 인수가 있으면 실행 전에 오류를 표시한다.
startup 입력 대기나 중단은 초기화 미완료이며 자동 성공으로 처리하지 않는다.
managed startup의 history 저장 등 차이는 [ADR](adr/0001-native-terminal-foundation.md)을 따른다.

## 여러 터미널 정의

프로젝트를 선택하고 Terminals에서 `n`으로 이름과 시작 폴더를 추가한다. 같은 폴더에 여러 셸을
정의할 수 있다. 개발 2개와 외부 테스트 3개 외에 추가 터미널도 가능하다. 폴더 접근 오류는 해당
정의에 표시하며 없는 폴더를 자동 생성하거나 HOME으로 대체하지 않는다. `F5`는 경로 상태를 갱신한다.

`e` 편집, `c` 복제, `d` 기본 선택, `Alt+↑/↓` 순서 변경, `Delete` 정의 제거를 사용한다.
임시 정의는 설정에 저장되지 않으며 `s`로 다음에도 사용할 정의로 저장한다. 프로젝트의 `m`은
루트 재연결 검토다. 기존 루트 아래 경로만 옮기고 외부 테스트 경로와 안정 ID를 보존한다.
정의 제거는 소스·스크립트·Git·실행 중 셸을 삭제하거나 종료하지 않는다.

`g`로 주 저장소나 관련 저장소를 명시적으로 연결한다. 다른 테스트 폴더를 선택해도 주 저장소
대상이 바뀌지 않는다. 같은 worktree를 사용하는 터미널들은 같은 파일과 브랜치를 공유한다.

CLI도 같은 검증과 revision 저장을 사용한다. 결과는 JSON이다.

```console
idk project connect example /path/to/source --shell /usr/bin/tcsh --source /path/to/setup.csh
idk terminal add example dev2 /path/to/source
idk terminal add example test1 /path/to/external/test1
idk project trust example
idk project trust example --yes
idk project inspect example
```

기본 저장 위치는 XDG의 `idk/v0.4` namespace다. `--data-dir /private/path` 또는 `IDK_HOME`은
별도 config/state/run을 사용한다. 사용자 소유의 안전한 디렉터리가 필요하며 손상·미래 schema를
빈 설정으로 덮지 않는다. `idk doctor`는 로컬 경로와 도구를 진단하고 경고가 있어도 exit 0이다.
자동 검사에서 경고를 실패로 다루려면 `--strict`를 사용한다.

## 터미널 열기와 재접속

Terminals에서 `Enter`는 새 셸을 열거나 같은 살아 있는 셸에 접속한다. `o`는 저장한 터미널을
기본 선택부터 순서대로 준비한다. 앞선 초기화가 입력을 기다리거나 완료를 확인하지 못하면 순서를
일시 중지한다. 해당 셸에서 입력을 처리하거나 `F8`로 다음 정의 준비를 명시적으로 계속할 수 있다.
`O`는 남은 준비를 취소하며 이미 열린 셸은 유지한다. 일부 경로·초기화 실패는 해당 항목에 남는다.

터미널에 입력할 때 `Ctrl+C`, `Ctrl+Z`, `Tab`, 방향키, `Esc`, 기능 키는 셸/프로그램으로 전달된다.
`Ctrl+g`는 관리 메뉴를 열고, 한 번 더 누르면 셸에 실제 `Ctrl+g`를 보낸다. 메뉴의 `q` 또는 `Esc`는
화면만 닫는다. 같은 사용자 호스트와 PTY가 살아 있으면 다음 접속에서 PID·alias·변수·현재 폴더를
유지하며 source나 cd를 반복하지 않는다. 다른 화면이 입력을 소유하고 있으면 명시적으로 인수해야
하며, 이전 화면은 읽기 전용이 된다.

`l`은 호스트에 남아 있는 모든 셸을 보여 준다. 프로젝트나 터미널 정의를 제거했어도 살아 있는 셸은
여기서 다시 접속한다. 임시 정의는 설정에 저장되지 않지만, 이미 시작한 임시 셸은 화면 종료 후에도
이 목록에 남는다. 호스트 재시작은 프로세스 복원이 아니다. 이전 실행은 불명확 상태로 표시하며
저장된 PID로 프로세스를 입양·종료하거나 source를 자동 재실행하지 않는다.

셸에서 `exit`하면 종료 상태를 유지한다. 다시 선택하면 새 셸과 초기화를 수행하는 **다시 열기**를
확인한다. 기본 묶음 열기도 종료한 셸을 자동으로 되살리지 않는다. `x`는 선택 셸, `X`는 프로젝트,
`H`는 호스트 전체 종료의 대상 검토다. `F2`로 확인하고 필요한 경우에만 `F3`로 강제 종료를 선택한다.
종료 요청과 실제 종료를 구분하며, 아직 끝나지 않은 작업은 대기로 남는다. 셸에서 분리된 프로그램이나
호스트 장애 뒤 남은 프로세스까지 모두 정리했다고 보장하지 않는다.

## 출력·검색·복사

비활성 셸의 출력도 계속 읽는다. 기본 scrollback은 메모리의 표시 행 2,000개이며 일반 입력/history를
별도 파일에 기록하지 않는다. `Shift+PgUp/PgDn`으로 이동하고, 메뉴의 `/`로 보관된 행에서 문자열을
검색한다. 검색은 표시 행 단위여서 화면 줄바꿈을 가로지르는 문자열은 연결해 찾지 않는다.

`y`는 현재 화면의 텍스트 복사 미리보기다. `F2`를 누를 때만 외부 터미널에 클립보드 요청을 보낸다.
외부 터미널이나 정책이 요청을 거부할 수 있으며 요청 전송을 복사 완료로 단정하지 않는다.
자식 프로그램의 OSC 클립보드 요청은 자동 실행하지 않는다. 붙여넣기는 한 번에 64 KiB까지이며
NUL/ESC가 포함되면 보내지 않는다. 출력·화면·큐 제한은 화면에 알린다.

종료 후 화면은 최근 16개만 메모리에 보관한다. 종료 상태 기록은 별도이며 화면을 비워도 자동 재실행의
근거로 삼지 않는다. 새 정의와 현재 셸의 초기화 정의가 달라지면 기존 상태를 유지하고 차이를 알린다.
물리 keypad 구분은 외부 터미널이 키 정보를 제공하는 범위에서만 인코딩하며 모든 키보드 확장을
지원한다고 주장하지 않는다.

CLI에서 실행 상태를 조회하거나 특정 셸에 직접 접속할 수도 있다.

```console
idk host status
idk session list
idk session start example dev
idk session attach <session-id>
idk session snapshot <session-id>
idk session close <session-id>
idk session close <session-id> --yes --takeover
idk session start example dev --reopen
idk host stop
idk host stop --yes
```

`host status`는 새 호스트를 시작하지 않는다. `session start`는 승인된 정의만 사용한다.
같은 버전 문자열이어도 바이너리가 다르면 기존 호스트를 보존하고 연결을 거부한다. 업데이트 중인
기존 실행에 접속하려면 해당 호스트와 동일한 바이너리가 필요하다. 등록 작업은 아래 Tasks/Results 화면에서 관리한다.


## Git 일상 작업

터미널 입력 중이면 `Ctrl+g`로 메뉴를 열고 `2`로 Git 화면을 선택한다. 대상은 선택 프로젝트의
주 저장소다. 테스트 터미널의 현재 폴더로 바뀌지 않는다. `v`에서 관련 저장소를 선택하면 그 저장소를
조회·변경하며, 저장된 주 저장소 연결은 유지한다. 화면 상단의 저장소 경로를 확인한다.
같은 worktree를 쓰는 터미널들은 파일·index·브랜치를 공유한다.

변경 목록에서 `↑/↓`로 파일을 고르고 `Enter`로 diff를 연다. `t`는 staged/unstaged를 전환하며
`z`는 목록으로 돌아간다. `Space`로 여러 파일을 선택한 뒤 `s`로 stage, `u`로 stage를 해제한다.
선택 표시가 없으면 현재 파일을 대상으로 한다. stage 해제는 파일 내용 버리기가 아니다.
개행·한글·옵션처럼 보이는 파일명도 실제 파일 단위로 처리하며, 화면에 보이는 이스케이프 표기를
명령어로 다시 해석하지 않는다. binary·미리보기 제한·submodule 미확인 상태는 별도로 표시한다.

`c`로 여러 줄 커밋 메시지를 작성하고 `F2`로 **실제 staged 변경 전체**를 검토한다. 다른 터미널에서
미리 stage한 파일도 포함된다. 검토 화면의 `Tab`은 파일 목록과 staged diff를 전환하고, `F2`는
검토한 커밋을 실행한다. index나 브랜치가 바뀌면 다시 검토해야 한다. 실패·취소·화면 이동 후에도
메시지 초안은 현재 UI 메모리에 남으며, UI를 종료한 뒤까지 보존한다고 보장하지 않는다.

`h`는 최근 커밋과 변경 파일, `b`는 브랜치 목록이다. 브랜치 화면의 `n`은 현재 커밋에서 새 브랜치를
만들고, `Enter`는 선택 브랜치로 전환할 내용을 검토한다. source를 바꾸는 전환과 pull에는 clean 상태와
등록 작업의 소스 사용 확인이 필요하다. 같은 worktree를 사용하는 Run이 준비·실행·취소 중이거나
정리가 미확인이면 전환과 pull을 제한한다. 취소 요청만으로 제한을 해제하지 않으며 실제 정리를
확인해야 한다. provider나 실행 상태가 unknown이면 idle로 간주하지 않는다. 상태·diff·stage·커밋·
브랜치 생성·fetch·push는 등록 Run의 소스 사용 때문에 막지 않는다. 외부 Git·편집기의 변경까지
차단하는 잠금은 아니므로 실행 결과의 source_changed와 미확인 상태도 확인한다.

`r`로 원격 목록을 열고 `f`로 fetch, `p`로 ff-only pull, `P`로 push를 검토한다. pull/push는 원격
브랜치를 직접 입력하며 실제 remote·URL·목적지를 확인한 뒤 `F2`로 실행한다. 상태 조회나 프로젝트
열기는 원격 통신을 시작하지 않는다. ahead/behind는 로컬에 남아 있는 마지막 정보이며 현재 원격의
상태를 새로 조회했다는 뜻이 아니다. force push, 자동 stash, hook·서명·인증 우회는 제공하지 않는다.

Git 실행은 기존 셸과 분리된 전용 터미널을 사용한다. hook·서명·인증 입력은 그 화면에 전달한다.
`Ctrl+g` 뒤 `z`는 Git 목록으로 돌아가며, `k`는 선택 작업에 취소를 요청한다. 실제 Git과 소유한 자식의
정리가 끝난 뒤 결과를 표시한다. 취소 전에 이미 변경된 파일·브랜치를 자동으로 되돌리지 않는다.
`F6`는 프로젝트 연결을 제거한 경우까지 포함한 Git 작업 목록이다. 다른 UI가 입력을 소유하면 인수를
확인한다. UI를 닫아도 실행 중 Git 작업을 자동 취소하지 않는다.

Git 전용 터미널의 입력·원문 출력은 일반 결과 JSON이나 자동 transcript에 넣지 않는다. 일반 결과는
실제 종료 상태, 재조회한 저장소 상태, 확인한 커밋과 주의 사항을 담는다. 결과가 불명확하면 재조회하고
검토한 새 작업을 선택한다. timeout이나 중복 클릭으로 commit/push를 자동 재실행하지 않는다.
`F5`는 선택 저장소를 다시 연결·조회한다. 새 UI의 인증 agent·CA·helper 참조를 사용하며, 오래된 검토는
실행 직전에 다시 검사한다.


## 등록 작업과 Run

`3`은 Tasks다. `n`으로 새 작업을 만들고 `e`로 선택 작업을 편집한다. 이름, csh 명령, 작업 폴더,
실패 정책(`stop`/`continue`), 로그(`raw`/`disabled`), 대화형 여부(`yes`/`no`), 제한 시간,
빌드 출력 폴더와 artifact 관계를 저장한다. artifact 관계는 파일의 동일 bytes를 증명하지 않는다.

작업 폼에서는 `Tab`/`Shift+Tab`으로 필드를 옮기고 `Enter`로 줄을 나눈다. `F6`으로 source의 경로와
literal 인수 목록을 추가하고 `F7`로 이름이 있는 실행 단계를 추가한다. source 인수는 한 줄에 하나씩
쓰며 빈 필드에서 `Enter`만 입력하면 빈 인수 하나가 된다. source는 최대 32개, 단계는 최대 64개다.
단계가 있으면 순서대로 실행하며, 없으면 주 명령을 실행한다. 실제 셸은 공통 초기화 → 작업 source →
작업 폴더 → 명령/단계를 수행한다. 입력을 기다리는 작업은 `interactive=yes`, `logging=disabled`로
등록한다. raw 로그를 켠 Run은 전용 터미널에서도 읽기 전용이며 키·붙여넣기를 전달하지 않는다.

`F2`는 정의만 저장한다. `Esc`는 현재 UI에 초안을 남기고 돌아간다. 다른 편집으로 revision이 바뀌어
저장에 실패하면 초안을 유지하며, `F4`로 최신 revision을 읽은 뒤 현재 초안으로 저장할지 결정한다.
목록의 `Enter`는 작업·폴더·source·단계·로그·제한 시간 검토를 연다. 처음이거나 입력이 변경되었으면
`F2`로 작업을 승인한다. 공통 초기화 승인이 필요하면 검토를 닫고 `t`에서 먼저 승인한다. 승인 후
다시 `Enter`로 검토하고 `F2`로 시작한다. 이미 승인된 동일 내용은 재승인하지 않는다.

실행 검토의 `F3`는 같은 작업을 병렬로 새로 실행할지 명시적으로 선택한다. 기본 시작은 같은 작업의
살아 있는 Run에 다시 접속하며 명령·source를 반복하지 않는다. 실행은 기존 개발/테스트 셸과 분리된
전용 셸에서 이루어진다. `Ctrl+g`로 메뉴를 열고 `q`로 UI를 닫아도 Run은 계속된다.

## 결과·원문 로그·Problems

`4`에서 선택 프로젝트의 Run을 보고 `Enter`로 상세 결과를 연다. `F9`는 제거한 프로젝트까지 포함한
전체 Run 목록이다. 작업·프로젝트 정의를 제거해도 보관된 Run은 이 목록이나 `idk run attach`에서
조회·재접속한다. `a`로 선택 Run 터미널에 접속하고 다른 UI의 입력 소유권을 인수할 때는 검토한다.
`r`은 현재 등록된 작업 정의를 검토해 다시 실행하며, 과거 결과의 명령을 자동 재생하지 않는다.

결과는 RunId, 정의 revision/digest, 실제 exit·signal, 단계별 결과, 제한 시간·취소 요청,
정리 확인, 시작/종료 시점의 소스 관찰과 artifact 관계를 구분한다. `k`는 취소, `K`는 강제 취소의
대상 검토다. `F2`로 요청한 뒤에도 실제 종료와 소유한 자식 정리가 확인될 때까지 완료로 간주하지 않는다.
호스트 장애 뒤의 `Unknown`은 저장된 PID로 복구하거나 종료하지 않는다. `u`는 해당 Run의 이전
프로세스가 정리되었음을 별도로 확인한 사용자가 정확한 Run과 source root를 검토하고 제한을 해제하는
동작이다. 결과 자체는 Unknown으로 남는다. Git의 Unknown도 `F6` 목록에서 `u`로 해당 작업·저장소를
검토하며 각각 별도로 확인한다.

상세 결과의 `l`은 raw 로그, `/`는 원문 문자열 검색, `p`는 Problems다. raw 로그는 터미널 viewport와
별도 generation·byte offset을 사용한다. `f`로 follow를 켜고 끄며 `↑/↓`로 스크롤하면 follow를 멈춘다.
UI의 텍스트 보관은 최대 256 KiB이며 제한 여부를 표시한다. 저장 로그의 recording/complete/limited/
write-failed/expired/partial 상태도 별도로 표시한다. logging을 끈 Run에는 원문 로그가 없다.
PTY가 합친 stdout/stderr의 개별 순서를 복원하지 않으며 제어 시퀀스를 화면 명령으로 재생하지 않는다.
검색 결과의 `Enter`는 해당 원문 byte 위치로 이동한다. `x`는 진행 중 조회·검색의 취소를 요청하며 Run을
취소하지 않는다. `z`는 Run 목록으로 돌아간다.

Problems는 Run과 log/source generation, 원문 위치, 진단 종류·메시지·파일·행을 표시한다. 개수가
실행 성공/실패를 결정하지 않는다. 누락·제한·소스 변경·미확인은 그대로 남긴다. 파일이 있는 항목의
`Enter`는 편집기 실행 검토를 열며 파일이 없는 항목은 원문 로그로 이동한다.

## 편집기 연결

Tasks/Results의 `E`에서 실행 파일의 절대 경로, literal argv 목록, 외부 GUI 허용 여부를 설정한다.
인수는 한 줄에 하나씩 입력한다. `{file}`은 `--` 뒤의 독립된 인수여야 하며 `{line}`/`{column}`은
검토한 숫자 위치로 치환한다. 예를 들어 vi 계열은 `+{line}`, `--`, `{file}`의 세 줄을 사용할 수 있다.
`F2`로 설정을 저장해도 편집기를 실행하지 않는다.

Problem의 `Enter` 검토에서는 정확한 Run·Problem·파일·행/열·실행 파일·각 argv와 소스/설정 변경 여부를
확인한다. `F2`를 눌러야 별도 편집기 터미널을 연다. 실행 직전에 파일·편집기·허용 root를 다시 검사한다.
편집기는 현재 launcher 환경과 검토한 프로젝트 폴더를 사용하며 공통 `.csh`를 다시 source하거나
기존 셸의 임시 변수·alias를 복사하지 않는다. 외부 GUI는 설정에서 명시적으로 허용한 실행 파일만
대상이며 GUI 창의 생존이나 파일이 과거 Run 시점의 snapshot임을 보장하지 않는다.

CLI에서도 같은 기록을 조회하고 검토할 수 있다.

```console
idk task list example
idk task editor example /usr/bin/vi --arg='+{line}' --arg=-- --arg='{file}'
idk run status <run-id>
idk run attach <run-id>
idk run problems <run-id>
idk run editor <run-id> <problem-id>
idk run editor <run-id> <problem-id> --yes
```
