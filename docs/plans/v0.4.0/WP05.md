**공개 순서:** 2026-09-07 사용자 지시에 따라 구현·공개 전 검증 후 릴리스하고,
사용자가 릴리스 결과물로 폐쇄망 실기를 수행한다. 이 문서의 수용 체크는 실행 계획이다.
공개 전 검사와 공개 후 대상 RHEL·정책 수용을 구분하며 미실행을 PASS로 바꾸지 않는다.
이미 승인된 개발·공개 범위와 사용자 원본/폐쇄망 환경 변경 권한을 구분한다.

## 목표

기존 C++/Qt·Python 명령과 .csh를 유지하면서 등록 작업의 환경·출력·실제 종료·취소를 추적한다. 직접 입력한 일반 셸 명령과 등록된 작업의 실행 계약을 혼동하지 않는다. 새 빌드 시스템이나 패키지 관리자를 만드는 작업이 아니다.

## 구현 계획

### 1. 등록과 실행 계획

작업 이름·명령/단계·cwd·프로젝트 환경 참조·실패 정책을 TUI로 등록한다. 기존 qmake/make/CMake 및 폐쇄망 스크립트, Python 테스트를 그대로 연결하고 idk 언어로 변환시키지 않는다.

open/import/설정 조회는 task 실행이 아니다. 첫 실행과 실행 정의 변경을 검토하며, 같은 승인 정의의 반복 빌드에 불필요한 확인창을 남발하지 않는다. 변수 인수는 실제 셸 규칙에 맞게 검증하고 임의 셸 문자열 합성/인용 오류를 방지한다.

### 2. 같은 셸의 초기화와 작업 실행

#41의 프로젝트 환경으로 **작업 전용 csh에서 초기화와 단계 명령을 같은 셸 안에 실행**한다. 일반 terminal에 사용자가 만든 임시 alias/변수를 자동 복제하지 않는다는 차이를 설명한다.

busy 일반 terminal에 명령을 주입하지 않는다. 대화형 실행이 필요하면 별도 owned task TTY로 연결한다. 인증/비밀 입력은 history/일반 로그와 구분한다. CLI와 TUI는 같은 실행 계획·cwd·환경을 사용한다.

실제 단계 종료코드를 수집한다. `tee` 같은 로그 파이프의 마지막 프로세스 코드로 빌드 성공을 오판하지 않도록 로그 수집을 분리한다. 셸 wrapper의 `status` 보존과 early exit/signal을 검증한다. 사용자가 제공한 스크립트가 자체 오류를 삼키는 경우까지 복구 가능한 것으로 주장하지 않는다.

### 3. Run/Operation 상태와 안전한 종료

생성 전 RunId/OperationId와 실행 의도를 기록하고 중복 start·시작 중 cancel·stop·retry·timeout을 구분한다. 같은 작업이 이미 실행 중이면 기존 실행으로 이동하는 기본 정책을 제공하고 명시적 병렬 실행 시 충돌을 확인한다.

idk가 소유한 process/group만 identity 재검증 후 정리한다. foreground job/자식 process와 daemonize/세션 이탈 같은 추적 한계를 명시한다. 취소 요청과 실제 종료를 구분하고 부분 정리 실패를 성공 취소로 표시하지 않는다. crash 후 결과 불명확은 자동 재실행/성공 처리하지 않는다.

### 4. Git source-use와 빌드 경합

#40의 계약을 실제 run provider로 구현하고 #43 Git에서 소비한다. run 시작과 소스를 바꾸는 branch/pull의 경합을 동일 worktree identity 기준으로 처리한다. 확인 직후 다른 실행이 시작되는 race를 막고 stale/unknown provider는 명시적 제한 상태다.

프로젝트·작업 정의·초기화 revision·시작 시 Git 상태·출력 descriptor를 연결한다. 실행 중 외부 Git/file 변경을 감지하면 결과 provenance를 갱신하되 외부 사용자의 수정을 무단으로 되돌리지 않는다. metadata 수집만으로 정확한 전체 소스 snapshot을 얻었다고 주장하지 않는다.

기존 build directory 구조는 존중하며 동일 결과 위치의 병렬 작업 충돌을 확인한다. build 파일/테스트 데이터를 자동 이동·삭제하거나 강제 clean하지 않는다.

### 5. 출력과 이력

#45가 사용할 bounded 출력 스트림과 로그 descriptor/논리 위치를 제공한다. PTY 통합 출력과 분리 stdout/stderr의 순서 보장 범위를 명시한다. 다른 프로젝트 화면을 보더라도 읽기는 지속한다.

memory·파일 용량·retention을 제한하고 disk-full/기록 중단/보관 만료와 실제 프로세스 실패를 구분한다. 비밀이 포함될 수 있는 raw 출력은 폐쇄망 로컬 정책을 따르고 외부 support 자료로 자동 전송하지 않는다. 로그 상의 제어 시퀀스를 일반 UI에 그대로 실행하지 않는다.

### 6. 여러 테스트 경로와 결과물 연결

여러 외부 test cwd와 선택 추가 초기화를 지원한다. 같은 프로젝트의 terminal이라는 사실과 특정 빌드 결과물을 테스트했다는 사실을 구분한다. 등록된 실행 파일/결과물 연결이 있을 때만 관계를 표시하고 없으면 미확인이다.

dirty tree/실행 중 소스 변경/이전 바이너리 사용 가능성을 표시한다. Git SHA만으로 결과물 동일성을 보장하지 않는다. 선택하지 않은 테스트 경로 덮어쓰기나 바이너리 자동 배포를 추가하지 않는다.
