**공개 순서:** 2026-09-07 사용자 지시에 따라 구현·공개 전 검증 후 릴리스하고,
사용자가 릴리스 결과물로 폐쇄망 실기를 수행한다. 이 문서의 수용 체크는 실행 계획이다.
공개 전 검사와 공개 후 대상 RHEL·정책 수용을 구분하며 미실행을 PASS로 바꾸지 않는다.
이미 승인된 개발·공개 범위와 사용자 원본/폐쇄망 환경 변경 권한을 구분한다.

## 목표

공개 전 필수 개발 흐름을 실제 패키지에서 검증하고 새 제품 기준으로 문서·CI·배포를 전환한다. 기존 idk 기능 전체 parity가 아니라 #39의 R01~R18/S01~S08이 완료 기준이다. 첫 공개 버전에 Git·실제 csh·외부 테스트 경로를 포함한 여러 terminal이 반드시 포함된다.

## 구현 계획

### 1. 요구사항과 증거 감사

각 R/S를 actual issue/PR/commit/test/evidence/environment/result로 수용한다. fixture PASS, 실제 csh/Git integration, WSL/Linux package, 대상 RHEL, 폐쇄망 정책 수용을 분리한다. 공개 전 필수 검사의 실패·미실행·확인 불가는 release blocker다. 사용자 지시에 따라 대상 RHEL·폐쇄망 정책 실기는 공개 후 수행하고, 해당 미실행을 전체 PASS로 대신하지 않는다.

폐쇄망 증거는 폐쇄망에 보관한다. 외부 기록은 정책상 허용된 판정에 한정하며 그조차 확인할 수 없으면 미확인으로 남긴다. 공개 전 검증과 공개 후 폐쇄망 최종 수용을 별개 상태로 기록한다. 공개 이슈·CI artifact에 폐쇄망 소스·로그·경로·계정을 넣지 않는다. 상태나 hash를 만들었다는 이유만으로 반출 허가로 해석하지 않는다.

### 2. 실제 패키지의 대표 시나리오

| 범위 | 필수 사례 |
|---|---|
| 프로젝트 | 개발2+외부test3, 추가6번째, 동일 경로 중복, 부분 missing/denied path, 두 프로젝트 |
| csh·환경 | 기존 startup/source 순서, alias/셸 변수, 독립 terminal 환경, init/start/live cwd, 재접속 source 반복 없음 |
| terminal | job control/전체화면/한글/resize/scroll/copy/paste, UI 종료·재접속, host 장애, 입력 takeover |
| Git | 테스트 탭에서 주 저장소 diff/stage/commit, pre-staged 변경, hook/auth/서명 실패, branch/pull/run 충돌, 명시 원격 |
| 빌드·결과 | 실제 exit/cancel/중복, log→problem→editor→재실행, stale 진단, 여러 test cwd·artifact 미확인 |
| 운영 | offline/NFS/noexec/권한/disk-full, 손상 번들, active host update, schema/activation 중단·복구 |
| 보호 | 사용자 source/.csh/.git/설정, 외부 process, 비밀·제어 시퀀스 경계 |

이전 실행에서 얻은 PASS를 소스/패키지 입력이 다른 후보에 적용하지 않는다. UI가 연결되는 것과 실제 백그라운드 작업이 살아 있는 것, terminal 지속과 Qt X11 창 지속도 구분한다.

### 3. 성능·학습 부담 수용

#40에서 정한 환경/fixture/예산으로 초기 진입·5terminal 준비·idle·Git status·출력 폭주·재접속을 측정한다. 불필요한 초기화 반복/terminal별 중복 polling/로그 누락/확인창 남발을 검사한다.

메뉴 안내만으로 프로젝트 연결→terminal 전환→Git→작업→결과→화면 닫기를 수행한 기록을 남긴다. 입력 횟수와 막힌 지점·키 충돌·좁은 화면/한글 문제를 기록하며 미측정이면 개선/PASS라 하지 않는다.

### 4. 구 구현·CI·문서 전환

사용하지 않는 구 코드/workflow/배포 항목/현행 문서를 정리하되 Git history와 기존 공개 릴리스는 보존한다. old binary를 숨겨 실행하는 영구 fallback을 요구하지 않는다. 기존 명령의 폐기·대체·비호환을 안내하고 사용자 데이터 삭제와 구분한다.

AGENTS/README/architecture/usage/closed-network setup/changelog와 실제 CLI·package manifest를 동기화한다. 새 검사에 맞춰 CI를 의미 있게 전환하며 gate를 삭제하거나 항상 성공으로 바꾸지 않는다. 새 파일 경로와 version source를 정리하고 prototype scaffolding이 최종 경로로 남는지 감사한다.

### 5. exact-main 후보와 공개 절차

source merge 및 필요한 CI 후 정확한 main SHA의 미공개 candidate를 생성/선정한다. source SHA/version/toolchain·target/manifest/artifact name·size·digest/native·복구 결과를 연결한다. candidate build 기반은 #40부터, package 검증은 #46에서 준비되어 있어야 한다.

공개 전 검증 후 2026-09-07 사용자가 승인한 범위에서 **동일 bytes**를 게시한다. 이미 승인된 공개를 반복 확인하지 않는다. 태그가 새로 다른 파일을 빌드하는 구조라면 검증 후보를 재사용하는 승격 방식으로 명시적으로 전환·검증한다. 코드/lockfile/패키지 입력 변경은 새 후보 검증을 요구한다.

공개 후 fresh-download로 이름·크기·digest와 기본 실행을 확인한다. 공개 RC는 기본 절차에 추가하지 않는다. 이번 태그/릴리스 권한은 문서 생성 자체가 아니라 2026-09-07 사용자의 구현·검증·릴리스 지시에서 온다. 폐쇄망 설치·정책 변경 권한으로 확대하지 않는다.

### 6. 공개 후 실기 인계와 완료 상태

#38의 진행표, #39 R/S 추적, WP별 actual PR·test·결과를 동기화한다. #38/#39는 단일 구현 PR의 `Closes` 대상이 아니다. 구현·공개 전 검증·릴리스 완료와 폐쇄망 최종 수용을 구분한다. 마일스톤의 구현·릴리스 범위를 완료하더라도 공개 후 실기의 담당(사용자), 릴리스/후보 identity, 미실행 항목을 수용 원장에 남긴다. 사용자가 공개 결과물로 대상 RHEL·정책 실기를 수행하고 허용된 판정만 추후 반영한다.

단순 결과 기록만을 위한 추가 PR은 기본으로 강제하지 않는다. 필요한 corrective PR은 허용하며 기존 7개 PR 예산을 바꿀 때 #38에 이유와 실제 mapping을 남긴다.
