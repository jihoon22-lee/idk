기존 코드를 재사용하지 않아도 되는 새 제품 기준을 정하고, 가장 위험한 csh/PTY/터미널·바이너리 호환성을 작은 실행물로 확인한다. **문서+실제 검증 실행물+최소 계약+CI를 B01 하나**에서 검토하며 문서만으로 완료하지 않는다.

기준 main: `cd23e45d34fab59dfc4a1e7fb2141574fc21a31d`. 구현 시작 시 변경분을 확인한다. Rust/Ratatui/PTY·화면 라이브러리는 후보이지 폐쇄망 실행이 검증된 확정 스택이 아니다.

## 구현 계획

### 1. 제품 기준·규약·릴리스 경계

#38/#39를 버전 관리하고 AGENTS의 기존 Python 하한/pyz/순수 Python/Zellij 규약은 legacy 경로에 유지하고, 신규 구현의 적용 경계와 검사를 실제 코드·ADR에 맞춰 명시한다. GUI 제외·최소 권한·원본 보호·폐쇄망 정보 보호는 유지한다. 과거 문서를 새 구현의 사실로 덮어쓰지 않는다.

legacy 전체 parity를 완료 조건으로 복사하지 않는다. 기존 명령의 유지/대체/비범위 판단은 사용자 안내 대상으로 기록하되 신규 기능을 삭제할 면허로 사용하지 않는다. main/이전 릴리스와 사용자 상태는 보존한다.

### 2. 실제 csh/PTY 호환성 검증

synthetic `.csh`로 실제 선택된 csh/tcsh를 PTY에서 실행한다. login/non-login startup, 초기화 cwd와 source 순서, alias/셸 변수/환경변수, 중첩 source, 입력 대기·실패를 검증한다. **초기화한 셸을 재실행해 내부 상태를 잃거나 .csh를 bash로 번역하지 않는다.** 생성한 보조 파일은 사용자 원본·시작 파일과 분리한다.

편집/완성/history, Ctrl+C·Ctrl+Z·fg, foreground process group, controlling terminal, resize, 전체화면 프로그램, UTF-8/한글 경로, paste·scroll/copy를 확인한다. 화면 parser뿐 아니라 터미널 질의 응답과 모드·TERM/terminfo 계약을 검증한다. 화면 연결 종료와 host 종료를 나누고 Linux/폐쇄망 logout 정책의 한계를 기록한다.

### 3. 기술·배포 ADR

선택 후보를 고정 toolchain으로 빌드하고 지원 target·ABI·외부 동적 의존성·license·배포 크기·터미널 필수 기능 결과를 기록한다. 실패한 필수 기능은 미지원으로 남기고 대안을 비교한다. 자체 엔진을 고집해 요구사항을 낮추지 않는다. 여러 backend 동시 지원 프레임워크는 만들지 않는다.

RHEL 목표와 WSL 개발 환경을 구분하며 현지 바이너리에 compiler/Python이 필요한지 검증한다. DNS/인증/폐쇄망 CA·NFS/noexec 등 미확인 조건을 목록화하되 환경 정책을 우회하지 않는다.

### 4. 최소 계약과 실제 소비자

Project/Repository/Terminal/Run ID, revision, request ID·version·bounds·deadline·cancel·중복 처리, host/UI 수명, 저장소 소유권을 정한다. 실제 소비자 없는 대형 framework와 daemon 다수를 만들지 않는다.

**Git source-use gate**는 WP04/WP05의 순환 의존을 피하도록 이 단계에 인터페이스와 동작 fixture를 둔다. repo/worktree identity에 대한 active/idle/unknown 및 source mutation과 run start 간 동시성 규칙을 표현한다. provider unavailable은 idle이 아니다. 관찰 후 변경 사이의 race와 외부 Git의 통제 한계를 명시한다.

프로젝트별 초기 환경의 출처와 접속별 runtime 환경(예: 인증 agent/display)의 적용 정책을 정한다. host가 처음 뜬 프로젝트 환경을 다른 프로젝트에 그대로 물려주는 문제와 재접속 시 만료된 참조를 검증한다. 전체 env/비밀을 공용 상태나 로그에 저장하지 않는다.

### 5. thin UI·CI·초기 패키지

thin TUI shell과 실제 csh/Git fixture 실행 harness, 신규 빌드·정적 검사·테스트·후보 bundle smoke를 만든다. 새 state namespace를 분리하고 로컬 저장 위치/동시 writer/권한·실패 정책을 검증한다. legacy와 새 코드가 같은 설정에 동시에 쓰지 않게 한다.

기존 Python 유지보수 검사를 유지하면서 신규 코드에 맞는 CI 검사를 추가·정의한다. 최종 배포·CI 전환은 WP08에서 실제 경계와 함께 검토한다. branch protection/required checks가 실제 존재하는지 확인한 뒤 대응하며, 검증을 삭제하거나 항상 성공으로 바꾸어 통과시키지 않는다. 문서/생성물은 같은 PR에 포함한다.

### 6. 측정과 인계

대표 5터미널 초기화, idle, 출력 폭주, 재접속, Git status 비용의 재현 조건과 예산을 정한다. 미측정은 미측정이며 성능 개선/PASS로 기록하지 않는다. 메뉴 안내만으로 기본 흐름을 수행하는 사용성 검증 절차도 고정한다.

## 제외

전체 제품 구현, 실사용 폐쇄망 .csh 외부 반출, 사용자 시작 파일 무단 수정, legacy 전체 기능 동등성, 실제 폐쇄망 설치 변경. 태그/릴리스는 WP08의 승인된 공개 순서에서 수행한다.
