**공개 순서:** 2026-09-07 사용자 지시에 따라 구현·공개 전 검증 후 릴리스하고,
사용자가 릴리스 결과물로 폐쇄망 실기를 수행한다. 이 문서의 수용 체크는 실행 계획이다.
공개 전 검사와 공개 후 대상 RHEL·정책 수용을 구분하며 미실행을 PASS로 바꾸지 않는다.
이미 승인된 개발·공개 범위와 사용자 원본/폐쇄망 환경 변경 권한을 구분한다.

## 목표

승인된 번들을 반입해 root 없이 실행하고 기존 셸/작업·원본·설정을 보존하며 갱신하는 운영 경로를 만든다. pyz나 구 기능 전체 이식을 강제하지 않는다. 가장 늦게 패키징을 처음 시도하지 않으며 #40부터 만든 후보 번들/ABI·저장 위험 검증을 완성한다.

## 구현 계획

### 1. 검증된 오프라인 실행 번들

선택 target/toolchain/dependencies를 고정하고 실행 번들·manifest·size/digest·license/notice·버전 정보를 생성한다. 같은 source와 테스트 결과에 artifact inventory를 연결한다. checksum은 파일 일치 확인이고 publisher 신뢰는 승인된 trust anchor/서명 또는 별도 검증 경로가 필요함을 구분한다.

압축 해제에서 절대 경로/상위 탈출/symlink/hardlink/특수 파일·권한·압축 해제 총 크기를 검증한다. 임의 postinstall script를 실행하거나 쓰기 가능한 다른 사용자의 디렉터리에서 구성요소를 자동 발견해 실행하지 않는다.

package-only 환경에서 compiler/Python/사외 network 없이 idk가 실행되는지 확인한다. 기존 csh/tcsh와 Git은 검증된 폐쇄망 실행 파일을 사용하고 임의 교체하지 않는다. 선택 도구 팩·유지보수 SDK는 실제 반입 승인 조건이 확인된 별도 범위이며 기본 필수 의존성으로 숨기지 않는다.

### 2. 사용자 상태·로그·실행 위치

프로젝트 설정/실행 이력/로그/host socket/cache/설치 generation의 소유와 보관 정책을 분리한다. #40에서 정한 host-local 저장 위치를 검증하고 NFS home을 SQLite WAL용 로컬 디스크로 가정하지 않는다. noexec/읽기 전용/권한 오류/disk-full을 빈 설정으로 위장하지 않는다. 정책 우회를 위한 대체 실행 경로를 만들지 않는다.

source/.csh/.git/legacy configs는 설치·연결·정리의 자동 변경 대상이 아니다. 새 schema/state namespace를 사용하고 잘못된/future schema를 조용히 초기화하지 않는다. 일반 터미널 입력/history와 로그 보관 범위를 혼동하지 않는다.

### 3. 활성 세션을 보존하는 업데이트

버전별 stage→verify→상태 검증/필요한 backup→activation→health→commit/recover를 설계한다. 여러 파일·DB·실행 프로세스를 하나의 OS transaction으로 바꾼다고 주장하지 않고 각 단계에 중단/재시도 경계를 둔다.

살아 있는 host/PTY가 사용하는 old generation을 보존하며 silent host restart를 금지한다. 새 client와 old host의 protocol mismatch에는 검증된 동일 버전 attach 또는 명확한 제한·종료 후 전환 안내를 제공한다. 이름이 같다고 다른 설치의 host/binary를 선택하지 않는다.

건강 검사는 버전/상태/IPC 및 무해한 fixture 중심으로 하고 실제 사용자 빌드·테스트·Git push를 자동 실행하지 않는다. 기존 실행을 중단해야 하는 단계라면 대상과 영향을 미리 보여 주고 승인받는다.

### 4. backup·rollback·downgrade·제거

state/schema 변화는 consistent backup과 복구 journal을 함께 설계한다. SQLite를 사용하면 live DB 파일 단독 복사 대신 검증된 snapshot을 사용한다. 손상/낮은 디스크/중간 종료 시 원본을 보존한다.

활성화 commit 전 recovery와 새 데이터가 생성된 뒤의 downgrade를 구분한다. 바이너리만 되돌린 후 호환되지 않는 schema를 열게 하지 않는다. 마지막 복구 수단이나 아직 active인 generation을 자동 정리하지 않는다.

legacy importer는 실제 필요한 최소 설정만 별도 정의/승인 후 제공하며 전체 호환을 약속하지 않는다. uninstall의 기본은 사용자 데이터 보존이다. 삭제 동작은 exact inventory·preview·명시 승인으로 분리한다. 영구 shell integration도 변경 preview/backup/복구 경로를 둔다.

### 5. 현지 진단과 폐쇄망 정책

doctor는 환경/초기화/도구/호스트/권한/패키지/상태 실패를 분류하고 현지에서 확인할 조치를 설명한다. 폐쇄망 로그/원문/경로/credential을 support archive로 묶어 외부 전송하는 흐름을 만들지 않는다. 마스킹만으로 반출 허가가 생기지 않는다.

기본 작업에 사외 서비스·자동 update check가 필요하지 않게 한다. 명시적인 내부 Git/미러 작업에서는 승인된 CA/인증을 사용하고 TLS 검증을 끄지 않는다. idk의 오프라인 정책이 임의 자식 프로그램을 OS 수준에서 sandbox한다는 뜻은 아니다.

## 필수 실패 검증

clean install, 기존 v0.3 설정 존재, active terminal/run, damaged package/manifest mismatch, archive traversal, 낮은 디스크, noexec/권한, stage/activation 중 cancel/crash, 새 client/old host 불일치, schema 실패, rollback 후 새 데이터 보존을 시험한다. 공개 전 지원 개발 환경의 실제 packaged 실행과 단순 빌드 성공을 분리한다. 대상 RHEL·폐쇄망 정책 실기는 사용자 지시에 따라 공개된 동일 결과물로 이후 수행한다.
