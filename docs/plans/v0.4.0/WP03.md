## 목표

프로젝트별 여러 실제 csh/tcsh 터미널을 이름 있는 탭/목록으로 전환하고 화면 연결과 셸 수명을 분리한다. 범용 멀티플렉서나 새로운 셸 개발이 목표가 아니다. 특정 Zellij/tmux 사용법 학습과 화면 분할은 요구하지 않는다.

## 구현 계획

### 1. 호스트와 클라이언트

#40에서 검증한 PTY/terminal-screen 처리를 host가 소유하고 CLI/TUI는 attach client로 둔다. 필요한 동안 동작하는 동일 사용자 host를 같은 바이너리의 내부 모드 등 최소 형태로 구성한다. 기본 TCP 서버·root·시스템 서비스 등록을 요구하지 않는다.

호스트별 실행 namespace와 socket directory/파일 소유·권한·peer identity·protocol version·request bounds/deadline을 검사한다. 중복 host 기동과 여러 설치/버전의 잘못된 연결을 막는다. 파일에 PID가 있다는 이유만으로 임의 process를 입양하거나 종료하지 않는다.

### 2. 여러 터미널과 간단한 UI

#41의 안정 TerminalId/이름/순서/기본 선택/초기화 상태/새 출력/exit를 표시한다. 프로젝트 기능 메뉴와 그 프로젝트의 terminal 선택을 구별한다. 개발 2개+외부 테스트 3개 및 추가 terminal이 좁은 화면에서도 선택 가능해야 한다.

기본 목록은 새 실행 정의다. 살아 있는 셸에는 재접속하고 source/cd를 반복하지 않는다. 닫은 셸은 종료 상태와 '다시 열기'로 표시하며 자동 부활시키지 않는다. 임시 terminal과 '다음에도 열기'를 구별한다. 일부 초기화/경로 실패는 해당 slot에 남기고 다른 terminal은 계속 사용할 수 있어야 한다.

### 3. 실제 터미널 입력·화면 호환

일반 키는 csh/실행 프로그램에 전달하고 관리 메뉴용 최소 키만 둔다. 메뉴 키 자체를 자식에게 전송하는 경로를 제공한다. terminal 입력 중 Ctrl+C/Ctrl+Z/Tab/방향키/Esc를 일반 TUI navigation으로 가로채지 않는다.

foreground job control, terminal query/response, application cursor/keypad와 alternate screen, resize·SIGWINCH, cursor/색상/문자 폭·UTF-8, paste/scroll/search/copy를 검증한다. #40의 TERM/terminfo 지원 범위를 정확히 사용한다. 메뉴 hide/show 후 focus와 입력 모드를 복원한다.

일반 터미널의 키 입력/history를 별도 자동 저장하지 않는다. scrollback은 bounded memory를 기본으로 하고 영속 저장을 추가하면 별도 정책·명시 선택을 둔다. clipboard 쓰기는 사용자 복사와 프로그램 OSC 요청을 구별하고 뒤의 외부 효과는 기본 제한한다.

### 4. 출력과 재접속

host가 숨겨진/비활성 terminal 출력도 지속 처리한다. memory/queue/scrollback/IPC를 제한하고 느린 client 때문에 자식 출력을 무기한 막지 않는다. 누락/잘림/보관 한계를 표시한다.

재접속은 현재 화면·커서·모드·sequence를 snapshot과 이후 event 경계로 동기화한다. 중복/유실과 resize race를 검증한다. 과거 escape sequence를 통째로 replay해 clipboard·외부 동작을 재실행하지 않는다. snapshot을 프로세스 메모리 복원이라고 설명하지 않는다.

### 5. 종료·입력 소유·재시도

화면만 닫기/개별 셸 exit/프로젝트 작업 종료를 분리한다. 한 terminal의 입력 연결 하나를 명확히 관리하고 takeover를 확인한다. 같은 terminal로 동시 입력이 합쳐지거나 stale client의 입력이 들어가지 않게 한다.

owned/borrowed 자원과 process identity를 확인한다. 중복 start/stop, 시작 중 취소, 정상 exit와 강제 종료, 부분 정리 실패를 구분한다. 프로젝트 전체 종료도 대상 preview와 안전한 정리 경계를 따르며 외부 process·다른 project·독립 multiplexer를 임의 종료하지 않는다.

### 6. 보장과 실패의 범위

UI crash/disconnect 뒤 host와 PTY가 살아 있으면 재접속한다. host crash/호스트 재부팅/로그아웃 kill 정책은 다른 장애이며 정확한 중단·불명확 상태를 남긴다. PID 목록만으로 복구 성공 처리하거나 명령을 자동 재실행하지 않는다. 폐쇄망 정책상 장기 process가 종료되면 그 정책을 우회하지 않고 제약으로 안내한다.
