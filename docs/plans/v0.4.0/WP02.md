## 목표

기존 프로젝트를 변환하지 않고 연결하고, 공통 개발환경 아래 여러 작업 경로의 터미널 정의를 저장한다. 첫 연결은 TUI로 가능하고 개인 설정에 저장한다. 프로젝트 내부 공유 설정 생성은 명시적 선택이며 자동 commit하지 않는다.

대표 사례: 동일 소스 경로의 개발 터미널 2개와 서로 다른 외부 테스트 경로의 터미널 3개. 같은 경로를 중복 사용해도 다른 터미널이다. 5개는 최대 제한이 아니다.

## 구현 계획

### 1. 프로젝트·저장소 연결

프로젝트 연결/최근 목록/이름 변경/root 이동·재연결/missing·offline 표시를 제공한다. ProjectId를 basename이나 현재 cwd와 동일시하지 않는다. 중복·별칭 경로는 preview로 처리하고 기존 프로젝트를 조용히 덮어쓰지 않는다.

Git 저장소·작업 트리 identity를 탐지하고 주 저장소로 연결한다. 프로젝트 등록이 git init/clone/checkout 실행을 뜻하지 않는다. 관련 저장소는 명시 선택하며 terminal의 cd가 Git UI 대상을 바꾸지 않는다. 비Git 경로에서도 환경/terminal 기본 기능은 유지한다.

### 2. 실제 csh 공통 초기화

#40의 계약으로 실제 shell 경로, login/startup policy, init cwd, source 순서·인수를 저장한다. 원본 .csh를 수정하지 않고 **초기화한 같은 셸을 유지**한다. shell 입력과 argv 인용을 구별하고 경로·인수의 공백/한글/특수문자를 검증한다.

선택 script/revision에 신뢰를 연결하고 변경 시 검토한다. nested source와 동적 실행의 추적 한계를 설명하며 모든 내부 의존 script 변경을 완벽 감지한다고 주장하지 않는다. 부모 startup 또는 source chain에서 이미 실행한 파일을 idk가 명시 정의 없이 한 번 더 추가하지 않는다.

### 3. 기본·임시 터미널 묶음

terminal template은 안정 ID, 이름, 순서, 시작 cwd, 기본/임시, 기본 선택, 선택 추가 초기화를 가진다. 프로젝트 외부의 합법적인 테스트 경로를 지원하며 사용자가 등록한 root와 접근 상태를 명확히 보여 준다.

이름·시작 경로만 입력하면 공통 환경을 기본 상속한다. 임시 terminal 추가와 '다음에도 열기'를 구분한다. 이름/경로 변경·삭제는 정의 수정이며 live 셸을 즉시 종료하거나 디렉터리를 변경하지 않는다. 소유 실행이 있는 항목 삭제 시 영향과 선택을 보여 준다.

### 4. 네 가지 문맥과 독립 환경

Project 소속 / init cwd / start cwd / live cwd를 분리한다. 새 셸은 지정 init 위치에서 source한 뒤 해당 start 위치로 이동한다. live cwd는 검증된 셸 연동 또는 확인 가능한 정보만 사용하고, 없으면 unknown이지 start cwd로 위장하지 않는다.

재접속은 source/cd를 반복하지 않는다. live env revision과 새 정의의 차이를 표시한다. 공통 절차로 시작하더라도 한 terminal에서 만든 alias/변수/경로 변화는 다른 terminal에 전파하지 않는다. host 최초 실행 환경의 다른 프로젝트 오염과 접속별 환경 갱신은 #40 정책을 따른다.

### 5. 초기화와 프로젝트 준비의 부수 동작

각 셸에 필요한 초기화와 프로젝트당 한 번 수행할 준비 작업을 구분할 수 있게 한다. 기존 .csh를 자동으로 분석·분해하지 않는다. 반복 실행 안전성이 불명확한 스크립트는 무조건 병렬화하지 않으며 실행 순서와 재시도 범위를 표시한다.

초기화 입력 대기/실패/도구 누락/경로 접근 실패를 구분한다. 한 테스트 경로 실패가 다른 terminal을 막지 않게 한다. 없는 경로를 홈 디렉터리로 대체해 성공으로 표시하지 않는다. 프로젝트 open은 terminal 환경 준비이지 빌드·테스트 자동 실행이 아니다.

### 6. 저장과 원본 보호

개인 절대 경로·내부 주소·비밀과 공유 가능한 프로젝트 정의를 분리한다. 공유는 승인된 내부 프로젝트 저장소 내 공유를 뜻하며 공개 idk repo로의 반출을 뜻하지 않는다. 새 state namespace에 검증·atomic write·revision 충돌 처리를 적용한다.

기존 0.3 설정은 자동 import/변환 범위를 결정하기 전 그대로 둔다. source/.csh/.git/개인 시작 파일을 연결 작업이 수정하지 않는다. 설정 파일이 없어도 연결 UI로 시작할 수 있고 잘못된 설정은 빈 기본값으로 조용히 덮지 않는다.
