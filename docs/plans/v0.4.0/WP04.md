## 목표와 의존 경계

개발→변경 검토→파일 선택→커밋→필요한 폐쇄망 원격 작업을 연결한다. 설치된 검증 Git 실행 파일과 기존 인증·hook을 우선 활용하며 GitHub 전용 기능으로 만들지 않는다.

#41 이후 read/plan과 핵심 변경 기능을 시작할 수 있다. 인증/서명/TTY는 #42의 실행 계약을 사용한다. active-run gate는 #40에서 정의한 fixture/인터페이스로 먼저 검증하고 WP05의 실제 provider와 통합한다. WP05 전체 완료를 Git 착수 조건으로 만들지 않되, 실제 provider 미연결 상태를 최종 PASS로 처리하지 않는다. 등록 작업과의 결합 테스트는 B05 및 최종 B07까지 추적한다.

## 구현 계획

### 1. 주 저장소·작업 트리 문맥

프로젝트의 주 Repository/Worktree binding을 검증하고 terminal cwd와 분리한다. 테스트 탭을 보고 있어도 Git UI는 프로젝트의 선택 저장소를 대상으로 한다. 관련 저장소는 명시 선택하고 서로 다른 저장소의 변경을 섞지 않는다.

동일 source 경로의 두 terminal은 같은 worktree와 branch를 공유함을 표시한다. 기존 linked worktree, unborn/detached HEAD, missing/moved repo를 처리하며 basename이나 .git 디렉터리 존재만으로 identity를 승인하지 않는다.

### 2. 상태·diff·파일 stage/unstage·이력

브랜치, 변경/untracked/conflict/staged 상태, staged/unstaged diff, 파일 단위 stage/unstage, 최근 commit/변경 파일을 제공한다. Git의 machine-readable 출력과 NUL 구분 경로를 사용한다. target Git 버전의 옵션 호환성을 확인한다.

큰 diff·binary·rename·공백/한글/개행·옵션처럼 보이는 파일명을 시험한다. 화면/로그 제어문자를 안전하게 표시한다. 조회에서 pager/editor/external diff/textconv 등 임의 helper가 조용히 실행되지 않도록 정책을 명시한다. submodule은 상태와 제한을 표시하고 무단 recursive update/동기화를 하지 않는다.

stage 해제는 변경사항 discard가 아니다. 첫 버전에 파일 삭제/reset/clean/자동 stash 같은 파괴적인 편의 동작을 몰래 추가하지 않는다.

### 3. 커밋과 실제 index

사용자가 terminal에서 미리 stage한 변경까지 포함한 **실제 전체 index**를 preview한다. message draft는 실패/취소/화면 이동에서 보존한다. 실행 직전 repo/index/HEAD를 재확인하고 동시 변경 시 stale review를 무효화한다.

hook·서명·credential·TTY 요구를 검증된 실행 경로로 처리한다. hook 실패/서명 실패/입력 대기는 정확히 표시하고 자동 `--no-verify`, 서명 비활성화, credential 우회를 하지 않는다. hook이 결과에 영향을 주는 경우 실행 후 상태와 실제 commit 결과를 다시 읽는다. 비밀번호/토큰 입력을 일반 로그에 저장하지 않는다.

### 4. 브랜치와 소스 사용 보호

branch 목록/생성/전환을 제공한다. 소스를 바꾸는 전환/pull 전에는 dirty/conflict 및 idk-managed run의 source-use gate를 확인한다. check와 run start/mutation 사이의 race를 #40 계약으로 처리한다. provider unavailable은 idle이 아니며 안전한 제한으로 표시한다.

외부 CLI의 Git 작업을 완전히 차단한다고 주장하지 않는다. 외부 변경을 감지하면 상태·결과 generation을 갱신하고 오래된 결과/변경된 초기화 정의를 알린다. 셸에 source를 자동 주입하지 않는다. 단순 read나 worktree를 바꾸지 않는 작업까지 이유 없이 차단하지 않는다.

### 5. 명시적인 원격 작업

fetch, ff-only pull, 대상 확인 push를 제공한다. 프로젝트 open/status 조회가 network를 시작하지 않는다. 로컬에 저장된 마지막 fetch 정보와 현재 원격 사실을 구분하고 offline/인증 실패/원격 오류를 표시한다.

push 전 실제 remote·destination branch·변경 범위를 확인한다. force push·upstream 자동 추측·자동 host-key 수락·TLS 검증 해제를 하지 않는다. 폐쇄망 CA/기존 인증 agent·credential helper 정책과 재접속 후 만료 참조를 #40/#42에 맞게 처리한다. token은 argv/history/log에 넣지 않는다.

### 6. 동시성·성능·결과

조회는 terminal 수가 아니라 저장소별 공유·single-flight·bounded 방식으로 수행한다. background status가 불필요한 write/lock으로 다른 Git 작업을 방해하지 않게 한다. mutation을 직렬화하되 외부 Git에 대한 보장 한계를 명시한다.

실제 종료코드와 실행 결과의 재조회로 성공을 판정한다. 중복 클릭/timeout/retry로 commit·push를 무조건 재실행하지 않는다. 결과가 불확실하면 확인 필요로 남기고 사용자 원본을 보존한다.
