## 판정 순서와 v0.4.0 공개 기록

사용자는 2026-09-07에 v0.4 구현·검증·릴리스 진행을 승인하고 **릴리스된 결과물로
폐쇄망 실기를 이후 직접 수행**하도록 지정했다. 원격 이슈에 남은 실기 후 공개 순서보다
이 사용자 지시를 우선한다. 요구사항을 삭제하거나 실기 미실행을 PASS로 바꾸지 않는다.

| 판정 범위 | 완료 조건 | v0.4.0 공개 당시 결과 |
|---|---|---|
| 구현 | R01~R18/S01~S08의 실제 코드·테스트·문서 연결 | B01~B07의 7개 PR 병합·증거 연결 완료 |
| 공개 전 검증 | 관련 fixture, 실제 csh/PTY/Git, 지원 개발 환경 패키지·복구·보호 검사 | 최종 main `a5d4bf9`의 CI·동일 후보 검사 PASS; 아래 공개 기록과 #47 참조 |
| 릴리스 | 검증한 exact-main 후보와 동일 bytes 게시, 다운로드 확인 | v0.4.0 공개 완료; 새 다운로드 7/7 전체 bytes 일치 |
| 폐쇄망 최종 수용 | 공개 결과물을 사용자가 대상 RHEL/폐쇄망 정책에서 검증 | 공개 후 사용자 수행; 미실행 |

공개 전 필수 구현·실행·패키지 검사의 실패/미실행/확인 불가는 공개 blocker다.
폐쇄망 실기 미실행은 이번 공개의 선행 blocker가 아니며, **폐쇄망 최종 수용의 미완료 항목**이다.
릴리스 설명과 인계에서 대상 RHEL·폐쇄망 정책의 미확인을 명시한다. 알려진 필수 기능 실패를
“실기는 나중에”라는 이유로 숨기거나 수용하지 않는다. 실제 발견된 중대 결함은 공개 전 검사의
실패 또는 공개 후 결함으로 기록하고 필요한 수정·새 후보 검증으로 해결한다.

## 결과를 기록하는 방식

상태는 PASS / 실패 / 미실행 / 확인 불가로 기록하고 skip·제한·부분 결과는 별도 설명한다.
계획한 명령, 이슈의 PASS 문장, mock 응답, PR 병합은 실행 증거 자체가 아니다.
대상이나 패키지가 다른 결과를 합쳐 대상 RHEL PASS로 만들지 않는다.

각 결과에는 다음 필드를 실제 값으로 연결한다.

| 필드 | 필요한 사실 |
|---|---|
| 범위 | R/S, WP/issue, 실제 PR |
| 소스 | 검증한 source SHA; 등록 당시 기준 SHA와 구분 |
| 실행 | 환경/도구 버전, 실행한 검사·명령, fixture/시나리오 |
| 결과 | 상태, 실제 관찰, 한계·누락, 재현/다음 조치 |
| 패키지 | 후보 식별, source/version/toolchain/target/빌드 입력, artifact 이름·크기·digest |
| 현지 증거 | 원본은 폐쇄망 보관. 외부에는 정책상 허용되고 확인 가능한 판정만 |

패키지 빌드 전에는 digest를 만들지 않는다. 구현 SHA나 PR을 추정하지 않는다.
재실행은 코드/입력 변경·실패·미해결 우려가 생긴 범위에 맞춰 수행한다.
필수 검사가 통과한 동일 입력을 이유 없이 반복하지 않는다.

## 요구사항 추적

아래 표는 v0.4.0 공개 전 실행한 검사의 범위와 결과를 보존한다. 공개 후 발견한 결함은
[별도 기록](#공개-후-발견-사항)을 함께 읽으며, 후속 버전의 검증에 이 PASS를 재사용하지 않는다.

“미등록”은 담당 WP가 실제 PR·SHA·검사 증거를 아직 연결하지 않았다는 뜻이다.
각 결과는 연결된 PR/작업 기록의 범위다. 일부 기능의 PASS를 전체 v0.4 요구 수용으로 확대하지 않는다.

[Native CI](https://github.com/jihoon22-lee/idk/actions/runs/34083556364)와 기존 Python CI가 통과했고,
실제 셸·terminal·Git fixture와 static/UBI 후보 검증은
[작업 기록](../../workthrough/2026-09-07-v0.4-foundation.md)에 연결한다.
이 증거는 B01 당시의 기반 검증이다. 최종 통합 증거는 아래 B05/B06/B07 기록으로 연결한다.

각 칸의 PASS는 명시된 fixture/프로그램/후보 범위다. 개발 라이브러리 테스트와 실제 배포 executable의 실행을 구분하며, 최종 main 후보에 이전 후보의 PASS를 재사용하지 않는다.

측정한다. 사용성은 메뉴 안내만으로 수행한 입력 횟수·막힌 지점·환경으로 기록한다.

## 공개 후 발견 사항

2026-09-07 재검토에서 위 공개 v0.4.0 binary에 타임아웃 취소 시 `runs.json` 저장 실패를
주입한 뒤 저장 경로를 복구했지만, 작업이 `Cancelling`·cleanup 미확인에 머물고 출력이
계속 증가하는 결함을 재현했다. 저장 실패가 없는 대조 실행은 `Cancelled`로 완료됐다.
메모리 상태가 먼저 바뀌어 타임아웃 검색과 호스트 재시도에서 제외되는 경로다.
R11/R14 및 S05/S07의 기존 PASS는 이 실패·복구 조합을 검증한 결과가 아니다.

v0.4.1 수정 범위는 durable 취소 의도 저장 실패 후의 자동 재시도와 회귀 검사다.
수정 결과·실제 검사·새 후보와 공개 identity는
[v0.4.1 작업 기록](../../workthrough/2026-09-07-v0.4.1-timeout-recovery.md) 및
[변경 이력](../../CHANGELOG.md)에 연결하며 이 원장의 v0.4.0 bytes·검사 결과는 보존한다.
새 결과물이 공개되면 [#53](https://github.com/jihoon22-lee/idk/issues/53)의 현지 실기 대상에도
그 버전과 실제 artifact identity를 명시한다. 현지 검증 전에는 PASS로 바꾸지 않는다.

## 공개 후 사용자 실기 인계

담당은 사용자이며 추적 이슈는 [#53](https://github.com/jihoon22-lee/idk/issues/53)이다. 최초 인계 대상은 위 v0.4.0 결과물이며,
패치 공개 이후의 실기 대상은 **#53에 명시한 버전과 artifact identity**를 따른다.
다른 WSL 빌드·개발 중 바이너리를 동일 후보로 취급하지 않는다.
공개 전에는 로컬에서 검증한 절차·지원 범위·알려진 제한을 준비하고 사용자는 허용된 현지 절차로 수행한다.

- 기존 소스·`.csh`·Git·설정을 보존하고, 허용된 rootless 설치 위치와 기존 csh/tcsh·Git을 확인한다.
- S01~S08을 대상 RHEL 8.10·실제 startup/CA·인증·NFS/noexec·로그아웃 정책 아래 확인한다.
- UI 재접속/host crash와 Qt X11 창 생존을 분리하고 외부 프로세스에 대한 보장을 확대하지 않는다.
- 현지에서 검사별 원본 증거와 실행 결과를 보관한다. 파일·로그·경로·계정 반출을 요구하지 않는다.
- 정책상 허용된 판정만 알려 줄 수 있다. 마스킹·요약·hash가 반출 권한을 대신하지 않는다.
  그 판정도 확인할 수 없으면 확인 불가로 남긴다.
- 실패가 발견되면 영향·재현 가능 범위·다음 조치를 기록한다. 수정이 필요하면 새 소스/후보를
  검증·공개하고 해당 결과물에 필요한 실기를 다시 연결한다.
