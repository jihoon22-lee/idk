# v0.4.0 프로젝트 TUI 요구사항과 수용 기준

원격 명세: [#39](https://github.com/jihoon22-lee/idk/issues/39).
원문 확인: 2026-09-07, 이슈 수정 시각 2026-09-05T14:57:27Z.
[로드맵](../roadmap/v0.4.0.md) · [수용 원장](../acceptance/v0.4.0.md).

R01~R18은 필수 제품 요구, S01~S08은 대표 전체 흐름이다. 구현상 어려움만으로 필수 기능을
다음 버전으로 넘기지 않는다. 기술 스택은 WP01의 실제 실험·ADR 대기다.
실제 구현 PR·SHA·실행 결과는 아직 미등록이며 아래 체크박스는 계획이다.

**공개 순서 변경:** 2026-09-07 사용자가 구현·검증·릴리스를 승인하고, 공개된 결과물로
폐쇄망 실기를 이후 직접 수행하도록 지정했다. 따라서 공개 전 구현/실행/패키지 검증을
완료한 exact-main 후보와 같은 bytes를 공개한 뒤 대상 RHEL·폐쇄망 정책 수용을 수행한다.
R/S 요구는 보존하며 공개 후 실기 미실행을 PASS나 공개 전 검증 결과로 대체하지 않는다.
원격 원문의 이전 공개 순서와 다른 부분은 로드맵의 승인 기록을 따른다.

## B. 반드시 해석을 고정할 경계

### csh 초기화와 터미널

초기화 위치와 최종 작업 위치를 분리하고, 원본 .csh를 bash로 번역하거나 초기화 후 새 셸로 바꾸어 내부 상태를 잃지 않는다. nested source와 동적 script의 모든 변경을 완벽 추적한다고 보장하지 않는다. 초기화가 입력을 기다리면 interactive 상태로 안내하며 무응답을 곧바로 성공/실패로 단정하지 않는다.

공통 초기화는 동일한 절차이지 실행 이후의 모든 셸 상태 공유가 아니다. UI 재접속은 source/cd 재실행이 아니다. host가 처음 실행된 프로젝트의 환경을 다른 프로젝트에 그대로 물려주지 않으며, 필요한 접속별 환경과 비밀의 적용·갱신 정책을 명시한다.

터미널 문자열 출력뿐 아니라 job control/입력 모드/전체화면/질의 응답/크기 변경을 검증한다. 과거 제어 시퀀스의 replay로 clipboard나 외부 동작을 실행하지 않는다. 일반 터미널 입력·history를 별도 자동 수집하지 않으며 scrollback과 등록 작업 로그의 보관 정책은 구분한다.

### Git과 작업 실행

Git 대상은 프로젝트 저장소 binding으로 고정한다. 같은 worktree의 두 터미널은 같은 파일/브랜치를 공유한다. stage 해제는 변경 버리기가 아니다. commit은 실제 index 전체를 보여 준다. 외부 Git과의 동시 작업·index 변경·hook이 결과를 바꾸는 경우를 재검증하고 idk가 외부 프로세스를 완전 통제한다고 주장하지 않는다.

최소 source-use gate 계약은 WP01 #40에 두고 WP04 #43이 소비, WP05 #44가 실제 run provider를 완성한다. provider unavailable은 idle이 아니다. 소스를 바꾸는 branch/pull에는 진행 중 run 보호를 적용하고, 단순 read 및 파일을 바꾸지 않는 동작까지 이유 없이 막지 않는다. 사용자 요청 없는 fetch/pull/push는 금지한다. 기존 인증과 서명을 지원 경로나 명확한 상태로 처리하되 TTY/Git 실패를 무시하지 않는다.

등록 작업은 지정한 환경으로 준비하는 별도 작업용 셸이다. 일반 terminal의 임시 변수까지 자동 복제하지 않으며 busy terminal에 문자열을 타이핑하지 않는다. PTY 통합 출력과 개별 stdout/stderr 사이의 순서 보장 범위, wrapper/script 실패코드 한계, 기록 누락 상태를 명시한다.

### 사용자 원본·필드 검증·공개

소스/.csh/.git/기존 설정 보호는 설치·import·정리가 승인 없이 원본을 바꾸지 않는다는 의미다. 사용자가 요청한 정상 Git commit/stage/branch 동작까지 금지한다는 뜻은 아니다. 새 구현에 legacy 전체 기능 동등성이나 Python fallback을 요구하지 않는다.

폐쇄망 증거는 폐쇄망에 보관하고 외부에는 정책상 허용된 판정만 기록한다. 마스킹이나 요약이 반출 허가를 만들지 않는다. 폐쇄망 실기 필수 항목의 미실행/실패/확인 불가는 공개 후 최종 수용의 blocker로 남긴다. 2026-09-07 사용자 지시에 따라 공개 전 검증과 릴리스는 진행하되 폐쇄망 수용을 완료 처리하지 않는다. Qt GUI 창 생존과 터미널 작업 생존, UI crash와 host crash의 복구 범위를 분리한다.

검증은 pure fixture → 실제 csh/PTY/Git integration → WSL/Linux packaged 실행 → 대상 RHEL 및 폐쇄망 정책 수용으로 구분한다. 각 증거는 source SHA, 환경, fixture/시나리오, 실행 결과와 제한을 기록하고 실제 패키지 검증에는 후보 digest·빌드 입력도 연결한다. 빌드 전 후보 digest를 만들지 않는다. 측정하지 않은 성능과 사용성은 미측정이다.

각 WP가 자기 기능을 검증하고 #47이 전체 구현·패키지·실기 증거를 최종 집계한다. 이슈 등록 또는 mock PASS를 native PASS로 대신하지 않는다. #38의 실제 PR mapping과 기준 변경을 함께 동기화한다.
