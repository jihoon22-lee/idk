# B06 — 오프라인 번들·설치 generation·복구

WP07/#46의 번들을 고정된 5개 정규 USTAR 파일로 제한하고, 사용자가 별도 신뢰 경로에서 얻은
SHA-256과 압축 bytes·모든 구성요소·manifest·라이선스 원문 inventory의 일치를 확인한다.
검증한 bytes를 메모리에 고정하므로 검토 뒤 입력 경로가 바뀌어도 새 파일을 실행하지 않는다.
checksum을 publisher 서명으로 설명하지 않는다.

설치는 새 private generation에 검증된 원본 archive도 보관한다. 단계별 journal과 원자적 current
symlink 전환, 무해한 version/schema 건강 검사로 활성화한다. 오류나 중단 복구는 설치 entrypoint만
되돌리며 살아 있는 host/run, 이후 생성된 workspace 데이터와 이전 binary를 보존한다. commit된
새 버전의 downgrade 및 schema migration은 지원하지 않고 원본을 보존한 채 거부한다. uninstall은
정확히 관리하는 두 symlink만 제거하며 generation과 사용자 데이터는 남긴다.

## 현재 실행 증거

- Rust bundle 검사 8 PASS: 압축/경로/링크/파일형식·크기 제한, digest/manifest/ELF 일치,
  input 교체 후 sealed bytes 사용, 기존 파일 보존, 라이선스 metadata 모순 거부.
- 설치 transaction 검사 6 PASS: stage/journal/activation/health/commit 각 중단 지점의 재시도,
  단계 전후 건강 검사 실패, 새 사용자 데이터 보존, 중단된 uninstall 복구, 원본 generation의
  재검증, future schema·committed downgrade·사용자 launcher 보존.
- 위 transaction 검사는 실행하지 않는 합성 ELF와 주입된 건강 검사로 상태 전이를 검증한다.
  실제 후보 실행/권한/noexec/disk-full/active host 통합 증거로 대체하지 않는다.
- 모든 target Clippy PASS. 최종 기능 통합, 실제 package 실행, CI와 공개 후보 검증은 진행 중이다.

전체 notice 수집과 실제 번들 재현 결과, 지원 환경의 설치·갱신·복구 검사 및 최종 PR/CI를 같은
작업 기록에 이어 연결한다. 대상 RHEL·폐쇄망 실기는 릴리스 후 사용자 수행이며 미실행이다.


## 실제 development 후보 검증

정적 runtime 5개, 전체 원문 296개를 수집하며 10개 Python 실패 fixture와 Python 3.10/3.14의 동일
archive 생성을 검증했다. 원문/정책/collector의 변경은 새 입력 hash와 후보를 요구한다.

  재접속, entrypoint 제거 후 셸 입력 유지 PASS. 실제 PTY fixture 1개 / 3.89초.
