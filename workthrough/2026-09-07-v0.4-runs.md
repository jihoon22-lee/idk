# B05 — 등록 작업에서 로그·오류·편집기·재실행까지

WP05/#44와 WP06/#45를 같은 묶음으로 구현한다. 등록한 환경과 단계는 별도의 실제 csh/tcsh 안에서
초기화부터 실행까지 유지한다. 정의 저장·검토·승인은 실행하지 않으며 승인한 정의의 반복 실행에는
새 초기화·작업 승인을 요구하지 않는다. 실행 검토에서 시작 동작은 명시적으로 선택한다. 일반 terminal의 임시 변수·alias를 복제하거나 바쁜 셸에 타이핑하지 않는다.

Run 의도를 생성 전에 기록하고 실제 exit·단계 결과·취소와 자식 정리를 구분한다. 같은 OperationId는
보관 중인 기존 결과를 반환하고, 같은 작업의 기본 중복 시작은 현재 Run으로 이동한다. source-use
lease와 Git branch/pull이 같은 host registry를 공유하며, 확인된 정리 전에는 lease를 해제하지 않는다.
복구된 Unknown은 저장된 PID를 입양하거나 성공으로 바꾸지 않고 명시적 현지 정리 확인으로만
제한을 해제한다. 기록 실패 시 취소 신호를 먼저 보내지 않고, finalization 재시도 중 shutdown을 완료로
보고하지 않는다. 외부 Git/파일 변경을 전체 snapshot으로 오인하지 않으며 untracked 내용 비교가
불명확하면 source_changed도 unknown이다.

Raw 로그는 Run별4MiB·64개 기록(최대256MiB), 비차단 수집 queue256KiB, 검색200개로 제한한다.
입력/인증 작업은 persistent logging을 Disabled로 설정한다. PTY 통합 출력은 stdout/stderr의 개별
순서를 복원하지 않는다. 누락·용량·파일 교체·만료와 실제 실행 실패를 별개로 표시한다.

Problems는 실제 raw byte 위치·RunId·log/source generation을 보존하고 C++/Qt/CMake/make/Python
진단을 수집한다. invalid UTF-8·제어 문자 때문에 파일명이 다른 이름으로 바뀌면 source 이동을
제공하지 않고 partial 및 원본 log를 남긴다. exit 성공/실패와 parser error 개수는 별개다.
편집기는 실행 당시와 현재 등록 root를 모두 확인하고 source/editor identity를 실행 직전에 재검증한다.
파일명은 `--` 뒤의 단일 literal argv이고 line/column만 숫자로 치환한다. 현재 launcher 환경에서
별도 editor를 열며 common `.csh`를 다시 source하지 않는다. GUI는 명시적으로 설정한 외부 도구만
허용하며 idk 자체 GUI나 창 생존을 보장하지 않는다.

## 독립 검토 반영

기록 전 descendant 신호가 나가던 취소 경합, worker 실패 시 session 문맥/재시도를 잃는 경로,
실패한 Unknown 확인 rollback, aggregate reply cache 한도, untracked source 내용의 unknown,
빠른 작업의 empty bootstrap 입력 경합을 수정했다. log에서 lossy UTF-8/Unicode control을 제거한
다른 파일명으로 editor가 열리던 경로와 Python bare Exception 누락도 실제 회귀로 고쳤다.

UI에서는 오래된 Tasks list 응답이 새 저장/승인 task 선택을 바꾸던 경합을 수정했다. revision을
비교하고 승인 task의 ID를 유지하며 draft/review 중 list polling을 제한한다. 새 작업·source argv·
여러 단계의 실제 실행과 늦은 목록 응답 회귀를 검증했다. 사용자 흐름의 최종 증거는 아래에 연결한다.


## UI와 키보드 흐름 — `fa086da`

Tasks에서 새 작업·이름 있는 단계·literal source 인수·로그/timeout/artifact 설정을 편집하고 저장,
검토·승인·실행으로 이어진다. Results는 Run별 실제 결과, bounded raw log/follow/search, Problems와
sealed editor 검토를 연결한다. 전용 Run/editor는 shell definition을 조회하지 않으며 제거한 프로젝트의
Run도 `F9`/RunId로 재접속한다. raw 로그를 켠 Run의 키·paste는 UI와 host 모두 차단하고 읽기 전용으로
표시한다. resize/조회와 명시 취소는 유지하며 logging Disabled인 대화형 Run은 실제 입력할 수 있다.

### S08 입력/동선 계측

`task_draft_approval_failed_result_log_search_problem_and_literal_editor`의 실제 이벤트를 계수했다.
사전 조건은 등록 프로젝트·공통 초기화 승인·기존 작업·설정된 독립 editor fixture다. 설정 fixture 생성과
대기/poll 횟수는 제외했다. 아래는 이름 수정 중 Esc로 돌아갔다가 초안을 다시 여는 동작까지 포함한
**scripted fixture**이며 최단 동선, 인간 사용성 연구 또는 기존 도구 대비 개선 수치가 아니다.

| 구간 | 실제 이동·실행·확인 키 | 횟수 |
|---|---|---:|
| Tasks → 편집 → 초안 보존/재열기 → 저장 | `3`, `e`, `Esc`, `e`, `F2` | 5 |
| 변경 작업 승인 → 재검토 → 시작 | `Enter`, `F2`, `Enter`, `F2` | 4 |
| Run 터미널 → Results 상세 | `Ctrl+g`, `4` | 2 |
| raw log → 검색 → 원문 위치 | `l`, `/`, `Enter`, `Enter` | 4 |
| Problems → editor 검토 → 실제 열기 | `p`, `Enter`, `F2` | 3 |
| 합계 | | **18** |

별도 텍스트 편집 키는 `Ctrl+U` **1회**, 붙여넣기 이벤트는 **2회/21자**였다. 이름 `Changed task`
12자와 검색어 `next-line` 9자이며 이를 사람이 21번 타이핑했다고 계산하지 않았다. raw terminal/input,
clipboard 동작을 이 측정에 끼워 넣지 않았고, 파일 생성·실제 실패 결과·editor argv까지 이어지는 흐름을
확인했다. 계측 출력은 `KEYBOARD_FLOW task-edit-to-editor`로 재현된다.

UI 개발 중 `/tmp` tmpfs 용량 부족으로 archive 생성/링크가 실패한 실행은 PASS로 계산하지 않았다.
이전 UI build cache를 정리하고 B05 target을 ext4로 옮겨 위 검사를 마쳤다. 별도 BSD csh UI 동선,
실제 사용자 키보드/외부 editor 창 사용성, 최종 정적 후보·UBI·PR CI·폐쇄망 실기는 이 UI 기록에서
검증하지 않았다. 폐쇄망 원본 자료·파일 반출이나 실제 환경 PASS를 전제하지 않는다.
