# v0.4.2 — 지연 source 프로브 경계화 수정의 패치 공개

2026-10-08 코드리뷰에서 확인한 v0.4.1 결함(지연된 source 관측의 무기한 대기, 세션 준비
완료 경로의 unwrap 재획득)의 수정만 담는다. 신기능·API·schema·protocol 변경이 없으므로
patch 버전 0.4.2로 공개한다. 수정 구현의 근거와 상세는
[지연 프로브 작업 기록](2026-10-07-deferred-probe-bounds-and-expiry.md)에 있다.

## 변경

- `Cargo.toml` workspace 버전을 0.4.2로 올리고 `Cargo.lock`의 `idk-workspace` 버전을 동기화했다.
- `CHANGELOG.md`의 `[Unreleased]` 항목을 `[0.4.2] - 2026-10-08`로 옮기고 compare 링크를 갱신했다.
  공개 후 실기 미실행 상태는 `### 후속 수용`에 유지한다.
- README와 `docs/closed-network-setup.md`, `docs/offline-workspace.md`의 반입물 버전을
  `idk-0.4.2-x86_64-unknown-linux-musl.tar.gz`로 갱신했다.
- 수용 원장의 "공개 후 발견 사항"에 리뷰에서 찾은 결함 조합과 v0.4.2 수정 범위를 기록했다.
  `closed-network-setup.md`의 #53 참조에도 closed 표시를 추가했다.

## 공개와 인계

[Native release promotion](../docs/native-release.md)을 따라 성공한 main push CI의
후보를 그대로 공개했다. 다시 빌드하지 않았다.

- main `3018d0186310dcaf34c6a79d30bff49a83ff4ba7`의 native run `37699450314`에서
  `release-native.py fetch`로 후보를 받고 `verify`로 오프라인 재검사했다.
  manifest는 `version=0.4.2`, `source.sha`와 `main_verification.expected_sha`가 모두
  동일 main SHA이며 `main_sha_verified=true`, `candidate_kind=exact-main`, `dirty=false`다.
- 검증된 SHA에 `v0.4.2` 태그를 만들어 push했다. `release.yml` run `37700898912`이
  게시를 완료했다.
- 릴리스 자산 7/7 전체를 새로 다운로드해 검증 후보와 `cmp` 비교해 bytes가 일치함을 확인했다.
  archive SHA-256 `b6c09ff8ca9e9e4a18219b8b320420dec983b962c3d24b79a1e5597d11a048fa`,
  바이너리 SHA-256 `ce2e543bd9cf093887d1a78c79f7f49dd643931194be101e46010b6f1b9f70b4`.
- 폐쇄망 실기 대상 버전과 artifact identity를 [#53](https://github.com/jihoon22-lee/idk/issues/53)
  코멘트에 인계했다. 이슈는 closed(기록 보존) 상태를 유지한다.

## 계획과 다른 점

- 브랜치·태그의 커밋/태거 이메일이 GitHub 이메일 비공개 정책으로 push 거부됐다.
  이전 푸시와 동일한 주소였으므로 원격 정책 변경으로 판단하고, git config는 바꾸지 않고
  해당 커밋·태그만 GitHub noreply 주소로 재작성해 push했다.
- 대상 RHEL·폐쇄망 실기는 계속 미실행이다. NFS host state/runtime은 지원하지 않으며
  업데이트는 기존 host를 재시작하지 않는다. 수정 적용에는 기존 작업을 마치고 원래
  generation으로 host를 정상 종료한 뒤 0.4.2 entrypoint에서 새 host를 시작해야 한다.
