# B04 — 프로젝트 Git 일상 작업과 전용 실행 터미널

WP04/#43의 R08~10/13/14/16과 S03/S04를 위한 Git core·호스트·UI를 연결했다.
UI checkpoint는 `1cccae0`, 호스트 checkpoint는 `d299a85`이며, 최신 B03 main을 합친
통합 기준은 `1c45e421fd1c111d698144d737cd941ea89eabc4`다. 별도 Python 경로는 변경하지 않았다.

Git 대상은 프로젝트의 주 저장소 또는 명시적으로 선택한 관련 저장소다. 테스트 터미널 cwd를
대신 사용하지 않는다. 상태·staged/unstaged diff·파일 stage/unstage·전체 실제 index 커밋 검토·
최근 이력/변경 파일·브랜치 생성/전환·명시적 fetch/ff-only pull/push 화면을 제공한다.
여러 줄 메시지 초안을 실패·취소·화면 이동에서 보존하고, 오래된 응답이나 index 변경이 현재
검토를 덮지 않도록 한다. 일상적인 파일 stage/unstage에 별도 승인 화면을 추가하지 않는다.

호스트가 sealed review/plan과 실제 파일 경로를 보관한다. UI는 상태 항목 번호와 검토/실행 ID를
전달하며 표시 문자열을 pathspec이나 셸 명령으로 변환하지 않는다. Git 조회·계획은 비동기 작업으로,
실행은 별도 소유 PTY로 처리한다. source-use lease는 실제 자식 정리와 결과 재조회까지 유지한다.
일반 결과·durable history에 인증 입력이나 PTY transcript를 넣지 않는다. 새 접속의 환경 참조를
검사하고, host 변경·불확실한 결과·중복 클릭으로 변경 명령을 무조건 재실행하지 않는다.

UI는 `crates/idk/src/ui/git*.rs`와 기존 입력/RPC 경로를 사용한다. 통합 테스트에서 발견한
빠른 키 입력 경합도 수정했다. 초기 session 목록보다 빠른 Enter도 입력 인수 검토를 거치고,
Git 하위 화면은 조회 완료 전에 해당 키 의미로 전환한다. 늦은 attach가 열린 커밋 편집기를
가려 입력 대상을 숨기지 않으며, 동일 저장소의 중복 준비 중 파일 동작은 추가하지 않는다.

## 실제 검사

Ubuntu 26.04.1/WSL, Rust 1.97.1, Git 2.53.0, tcsh 6.24.13에서 실제 셸 경로를
`IDK_TEST_SHELL`로 지정했다. UI 검증은 개발 트리와 통합 코드 `1cfaa2a`에서 실행했다.

- `cargo test --locked -p idk-workspace --lib --test ui_git --test ui_terminal --test ui_projects`:
  통합 코드 `1cfaa2a`에서 lib 35, Git UI 4, 프로젝트 UI 12, 터미널 UI 6 — 총 57 PASS.
- `ui_git`는 개행/한글/옵션형 파일명 stage·diff·unstage, 외부에서 미리 stage한 파일을 포함한
  전체 커밋, stale index와 메시지 초안, 관련 저장소 선택, 이력, 브랜치 생성, 명시적 fetch/push를
  실제 Git 저장소에서 확인한다. source-use 미연결 시 pull은 FETCH_HEAD를 바꾸기 전에 제한된다.
- 실제 외부 UI PTY에서 hook의 숨김 입력·실패·취소를 확인했다. 바쁜 기존 셸에 인증 입력이
  전달되지 않았고, 결과 JSON에는 입력이나 prompt 원문이 들어가지 않았다. 실패/취소 후 초안과
  staged 파일을 유지하고 실제 커밋 수를 확인했다. fixture hook 검증이며 실제 폐쇄망 인증 검증은 아니다.
- 한글 여러 줄 편집, 늦은 diff/이전 context 응답 무시, 편집 중 늦은 attach의 표시/입력 보존을
  synthetic UI 검사로 확인했다.
- `cargo clippy --locked -p idk-workspace --all-targets -- -D warnings`: PASS.
- 변경 범위 `git diff --check`: PASS.
- 호스트 담당자의 post-merge 검사: `host_git` 4, `git_core` 6,
  `host_runtime` 11(`--test-threads=4`) PASS. `host_runtime`의 기본 11개 동시 실행 첫 시도는
  5개가 debug 호스트 기동 제한을 넘겼다. 동시성 4의 결과를 기본 동시성 PASS로 바꾸지 않는다.
- debug native probe는 실제 Git status·파일 stage·전체 index 검토·commit·history PASS를
  기록했다. Git status 73 ms(예산 1,000 ms), 셸 준비 663 ms, 재접속 131 ms, RSS 17,932 KiB다.
  이 측정은 release 후보나 실제 폐쇄망 환경 결과를 대신하지 않는다.

## 남은 통합과 제한

B04의 source-use 계약은 fixture로 검사했으며 **실제 RunRegistry provider 연결은 B05**다.
현재 provider unavailable은 unknown이며 branch switch/pull을 제한한다. mock/fixture PASS를
실제 작업 실행과의 경합 검증 PASS로 바꾸지 않는다. 변경 가능한 외부 Git 프로세스를 완전히
잠그는 보장도 하지 않는다.

후속 main/후보 패키지의 전체 검사·native Git probe·PR/CI 결과는 통합 담당자가 이어 기록한다.
이 기록은 아직 실행하지 않은 후보나 폐쇄망 실기를 PASS로 주장하지 않는다. 폐쇄망 실기는
사용자가 공개 결과물로 후속 수행한다.
