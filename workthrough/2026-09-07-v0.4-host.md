# B03 — 실제 터미널 화면·사용자 호스트·재접속

WP03/#42, R01~07/14/16, S01/S02/S05/S06의 호스트와 화면 연결을 구현한다. 사용자 호스트가
PTY를 유지하고 TUI는 현재 셀·커서·모드와 generation을 받아 그린다. UI 종료는 detach이고 기존
셸에 다시 접속할 때 source/cd를 반복하지 않는다. 임시 정의, 제거한 정의의 살아 있는 셸도 목록에서
접속하며 종료·불명확 상태의 재실행은 명시적 확인을 거친다.

입력 소유 epoch, 실행 파일 SHA와 host UUID, bounded frame/queue/절대 deadline, 변경 요청의
한시적 중복 결과 보관을 연결했다. 입력 실패 뒤 자동 재전송하지 않으며 빠른 타이핑은 동일 대상/
epoch별로 묶는다. 초기화 준비는 별도 worker에서 수행하고 actor가 기록한 뒤 bootstrap을 전달한다.
기본 터미널은 순서대로 준비하고 입력 대기/미확인은 일시 중지한다. 종료 검토는 정확한 대상 목록과
실제 exit를 구분한다. ledger는 환경·입력·PID를 보관하지 않고 host 교체 시 이전 live를 Unknown으로
복원한다. 로그 저장이나 프로세스 메모리 복원이 아니다.

검토·실행에서 발견한 결함을 함께 수정했다. IPC 성공 `null` payload가 사라지던 역직렬화,
가득 찬 socket backlog와 FIFO identity 검사 대기, 같은 큰 바이너리의 중복 hash로 인한 debug
startup timeout, 빠른 키 입력 누락, 임시 종료 기록의 용량 오계산과 saved/transient ID 충돌을 다뤘다.
출력 제한/실제 I/O 오류와 종료 화면의 보관 만료를 표시한다. 최종 PTY 수집을 EOF 전에 끝내면
잘림 가능성을 표시하고 generation을 바꿔 이미 연결한 화면에도 전달한다.

## 실행 증거와 현재 남은 검증

- WSL Ubuntu 26.04.1 / tcsh 6.24.13 / Rust 1.97.1에서 중간 전체 workspace 90 PASS.
  별도 terminal core 실제 PTY 4개를 포함한 담당 검증도 PASS.
- Host 통합 7개: 프로젝트 2개/셸 6개, source-once, 중복 입력 요청, takeover와 오래된 입력/resize/
  detach 거부, 초기화 대기와 실패 격리, 명시적 force, host 장애/Unknown, 임시 셸 다시 열기.
- UI 기존 12개와 신규 실제 터미널 6개 PASS. 실제 PTY의 F1/application cursor/메뉴 키 전달,
  한글 alternate screen/resize, Ctrl-Z/fg/Ctrl-C, 화면 재접속 뒤 동일 PID/변수/source 횟수 포함.
- CLI 실제 연결→상태 변경→detach/중복 start→close/reopen→프로젝트 정의 제거 후 셸 접속→호스트
  종료 흐름 PASS. 무관한 fixture 프로세스가 살아 있음을 확인했다.
- 독립 검토로 추가한 최종 출력 잘림/generation 회귀, 출력 제한 및 화면 만료 UI 검증 PASS.
- 동일 debug 실행 파일의 확장 probe: 5개 준비 641 ms, 재접속 첫 화면 138 ms, idle host RSS
  15,596 KiB. 이는 debug 관측이며 공개 후보의 측정으로 재사용하지 않는다. probe 강제 종료 시
  probe 전용 자식 host도 끝나는 실제 검사 PASS. 정상 UI host의 detach 수명 정책은 그대로다.

**최종 검증 진행 중:** 일반 background job이 force-close 뒤 남는 독립 재현을 바탕으로,
호스트 subreaper와 확인된 자식의 종료·회수, SID를 유지하는 unreaped leader 계약을 보완 중이다.
이 수정의 실제 회귀 및 최종 후보/UBI/CI 결과는 완료 후 아래 기록으로 갱신한다. 중간 빌드는 입력
변경을 감지해 후보 게시를 거부했으며 그 산출물을 패키지 PASS로 사용하지 않는다.

다른 UID의 실시간 peer 검사는 아직 미실행이다. 소켓의 소유·권한과 SO_PEERCRED 검사는 body 할당
전에 적용하며 같은 UID를 완전한 보안 sandbox로 설명하지 않는다. 대상 RHEL·폐쇄망 정책 실기는
공개 후 사용자 수행으로 남긴다. Git 작업 TTY/실제 source-use provider와 등록 run은 B04/B05 인계다.
