## 재현과 수정

| 결함 | 수정 전 재현 | 수정 원칙 |
|---|---|---|
| 중복 Run 대기자 취소·실패 | host 원장에 같은 Run의 session 두 개, 다음 host 시작 거부 | 대기자 결과와 실제 실행 소유권 분리 |
| 동시 시작과 이력 한도 | 완료 이력 63개와 예약 2개가 원장 65개로 저장됨 | 저장 이력과 예약 용량을 함께 제한 |
| 종료 후 timeout | exit 0·cleanup 확인 뒤 느린 Git 관찰 동안 Cancelled로 변경 | 실행 종료와 source 관찰·저장을 별도 단계로 관리 |
| doctor PID 재사용 | listener가 없는데 다른 살아 있는 PID 때문에 strict exit 0 | 검증된 접속의 instance·PID와 기록 대조 |
| rename Stage | rename 행만 선택해도 재생성한 미선택 source가 index에 추가됨 | Stage는 worktree, Unstage는 index 변경에 맞춰 경로 확장 |
| nested Git 조회 | porcelain의 `? nested/`를 경로 이탈로 거부함 | 디렉터리 marker만 분리하고 파일명 bytes·경로 검증 보존 |
| 루트 재연결 출력 경합 | cwd·artifact는 새 루트, build_outputs는 옛 루트에 남음 | 출력 예약도 재연결 검토와 경로 변경에 포함 |
| 최종 저장 실패와 retention | 저장 재시도 전 실행 기록 또는 host session이 정리되어 로그·lease나 재시도가 사라짐 | 실행 기록·session을 성공 응답까지 보존하고 종료도 실제 저장 완료를 확인 |

회귀는 수정 전 실패를 확인한 뒤 수정본에서 통과시킨다. 느린 source 관찰은 실제 Git
fsmonitor와 marker로 동기화하며 timeout 경계는 별도의 명시 시계 검사로도 대조한다.
완료 요청과 완료 확인은 Pending/InFlight/Done으로 구분하고, registry 조회에 실패해도
원래 session으로 결과를 전달한다. 65개 중복 요청이 종료 대기 session의 정리를 유발하는
실제 경로와 저장 실패 후 복구를 함께 검증한다.
프로세스를 만들기 전 준비 실패도 종료 기록 저장에 실패하면 원래 오류와 재시도를
보존하고, 저장 복구 뒤 명령을 재실행하지 않은 채 Failed로 확정한다.
재현에 사용한 저장소·host·셸은 테스트가 소유한 임시 자료이며 사용자 작업을 재실행하지 않는다.

이미 생성된 중복/한도 초과 원장은 typed health가 거부하고 원래 bytes·로그를 보존한다.
설치 health 실패와 recovery 뒤에도 기존 generation과 committed version floor가 유지되는지
합성 archive fixture로 확인한다. 실제 후보 설치 검증과 구분한다.
현지 대응은 [오프라인 복구 안내](../docs/offline-workspace.md#기존-runsession-원장의-불일치)를 따른다.

## 검증 기록

변경된 source·환경·후보를 기준으로 결과를 기록한다. 이전 리뷰의 통과 결과를 새 코드나
새 package의 PASS로 사용하지 않는다. 로컬 관련 회귀와 전체 gate, PR CI, exact-main 후보,
공개 후 다운로드 결과는 아래 기록과 실제 PR·릴리스에 연결한다.

- runtime 묶음의 최종 제품 코드: 전체 Rust 242 PASS/5 ignored, actual tcsh PTY 4 PASS,
  BSD csh 초기화·프로젝트·Run·host Run 65 PASS, fmt/Clippy PASS.
  로컬 전체 검사는 다른 작업 부하를 고려해 `RUST_TEST_THREADS=2`로 수행했으며 CI는 4를 유지한다.
  ignored 4개는 위 actual PTY로 실행했고 package 1개는 실제 archive 검증에서 별도로 실행한다.
- Git 묶음의 관련 통합 39·parser 1, 프로젝트 재연결 출력 충돌 1 PASS.
  최종 0.4.3 통합 코드와 main 후보는 별도로 검증한다.
- 기존 불일치 원장의 health/activation 보존 fixture 1 PASS.
- Python 3.10/3.14 각각 packaging 10·release 13, Ruff check/format,
  workflow actionlint PASS. 실제 제품 실행에 Python이 필요하다는 뜻은 아니다.
- 추가 retention·준비 실패 저장 복구의 RED→GREEN 회귀와 독립 코드 검토도 통과했다.
- 최종 통합 검사 중 Git UI의 연결 오류 1건과 전체 메뉴 검사의 화면 전환/연결 오류를
  관찰했다. Git UI는 별도 실행과 다음 전체 실행에서 통과했다. 연결 오류의 최초 원인은
  확정하지 않았으며 이후 최종 통합·CI·동일 후보의 실행 결과를 별도로 확인한다.
- 전체 메뉴의 resize 경합은 수정 전 실행 파일에서도 재현했다. 저장된 작업 목록·좁은 화면의
  redraw를 기다리고, 편집기 fixture의 파일 생성과 argv 쓰기 완료를 구분하도록 검사를 보강했다.
  고정 sleep·키 재전송·timeout 증가는 없고 기존 navigation 50/editing 6/paste 12를 유지한다.
  원래 제품 코드에서 UI Run 5개와 위 전체 검사가 통과했다.
- 첫 PR CI의 정적 후보 doctor 검사에서 새 fixture의 `ETXTBSY`를 확인했다. 실행 파일을
  복제·쓰기·실행하는 동안 같은 테스트 프로세스의 다른 fork가 겹치지 않도록 fixture를
  직렬화했다. 보강 후 doctor CLI 4개와 관련 Clippy가 통과했다. 제품 실행·진단 의미와
  timeout은 바꾸지 않으며 새 CI·후보에서 다시 확인한다.

## 공개와 정리

공개는 [릴리스 프로토콜](../docs/native-release.md)에 따라 성공한 main push CI의
검증 artifact를 다시 빌드하지 않고 승격한다. 입력이 변경되면 새 후보를 검증한다.
공개 뒤 새로 다운로드한 7개 asset의 이름·크기·digest·전체 bytes와 실제 `--version`을 비교한다.
실제 main SHA·native CI·후보/공개 identity는 릴리스 기록과
[#53](https://github.com/jihoon22-lee/idk/issues/53)(closed, 실기 미실행 보존)에 연결한다.

병합·공개 확인 후 이번 작업의 branch·worktree·임시 fixture와 테스트 프로세스를 정리한다.
사용자 데이터, 기존 공개 릴리스, 다른 작업 공간·프로세스는 정리 대상에 포함하지 않는다.
