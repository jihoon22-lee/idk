WP08/#47의 공개 전 요구사항을 R01~R18/S01~S08과 실제 실행 증거에 대조한다. B01~B06의

## 실제 배포 바이너리의 CLI/host와 전체 메뉴

`e3822d8`은 테스트6스위트의 spawn·client 연결·cleanup을 공통 IDK_TEST_LAUNCHER로 선택하게
한다. 미설정 시만 Cargo build binary를 사용하며 명시한 경로는 absolute existing file이어야 한다.
제품 코드를 바꾸거나 실제 검사를 생략하지 않는다. B06의 같은 static SHA
`12b03aee877a728de08083120d04b97b56db8edf8ca86765d4476adc3a6dbee8`로 다음 **40 PASS**다.

`4043eb4`(원본 `0d5d71c`)의 `ui_runs::complete_menu_flow`는 실제 outer PTY에서 같은 static
후보를 실행한다. 사전 설정은 합성 Git/파일/에디터뿐이며 TUI에서 프로젝트 연결·source·신뢰 승인→
외부 cwd terminal→주 Git diff/stage/commit→한글 task→실제 exit7→Problems/에디터→q를 수행한다.

기존 설정 bytes를 보존했다. fixture는 writable 화면을 확인한 뒤 입력하고 명령을 재시도하지 않는다.

## 최종 main 후보·공개 판정

소스 병합·필수 CI 후 `release-native.py fetch/verify`로 정확한 main 후보를 선정한다.
해당 source/version/toolchain/manifest/artifact ID·이름·크기·SHA와 same-candidate 기능/설치/
복구·메뉴 검사, 태그/게시·fresh-download7파일 비교를 [#47](https://github.com/jihoon22-lee/idk/issues/47)의 실제 공개 기록에 남긴다.
이 파일 작성 당시 최종 main 후보 선정과 게시/다운로드는 미실행이며 사전 PASS로 처리하지 않는다.

같은 bytes 게시와 새 다운로드 검증까지 끝나야 구현·릴리스 마일스톤을 완료한다.
사용자 현지 실기는 [#53](https://github.com/jihoon22-lee/idk/issues/53)에 대상 릴리스/번들 identity와
미실행 S01~S08을 연결하며, 인계 자체를 폐쇄망 PASS로 표시하지 않는다.

최종 B07 통합 파일의 all-target Clippy `-D warnings`, cargo fmt, Ruff check/format,
세 workflow actionlint/ShellCheck와 diff 검사 PASS. 제품 동작을 바꾼 추가 Rust 수정은 없으며
추가 candidate 선택/S08 검사와 CI·문서 전환을 같은 B07 PR로 묶었다.
